## 二、C# / Unity 基础

### Q5：C# 里值类型和引用类型的区别？对 Unity 开发有什么影响？

**答：** 值类型（int、struct 等）存在栈上，赋值时拷贝；引用类型（class）存在堆上，变量存的是引用。Unity 中 `Transform`、`GameObject` 是引用类型；`Vector3`、`Color` 是 struct 值类型。值类型做临时计算可减少 GC；引用类型要注意空引用和生命周期。做性能优化时，我会避免在 Update 里频繁 new 引用类型对象，改用对象池或缓存。

---

### Q6：Unity 生命周期里 Awake、Start、Update 的区别？

**答：** Awake 在脚本实例化时调用，适合初始化自身引用、GetComponent；Start 在第一帧 Update 前调用，适合依赖其他对象的初始化；Update 每帧调用，适合输入、逻辑驱动。FixedUpdate 按固定物理步长调用，适合物理和与帧率无关的逻辑。我在项目中会把重逻辑从 Update 拆出去，用事件、状态机或定时器驱动，避免每帧空转。

---

### Q7：协程（Coroutine）的原理和使用场景？

**答：** 协程是基于迭代器的分时执行机制，用 `yield return` 把长耗时操作拆成多帧。常用于异步加载、延迟执行、分帧实例化、动画序列。我在宠物乐园里用协程配合异步加载和对象池，分帧创建大量 3D UI，避免单帧卡顿。注意协程绑在 MonoBehaviour 上，对象销毁时要 StopCoroutine，否则会报错。

---

### Q8：Unity 中如何实现热更新？你的实际经验？

**答：** 常见方案有 ILRuntime、HybridCLR、XLua 等。我在途游和趣加项目里都用过 **Lua（XLua）+ C# 混合开发**：业务逻辑、UI 部分放 Lua，底层框架和性能敏感模块用 C#。在《富豪麻将》里还参与过 **C# 重写 Lua 代码以支持 C# 热更**。SLG 项目采用 Business / DataHelpers / Datas 三层架构，Lua 层做业务，C# 层做数据和框架，便于迭代和热更。

## 三、Lua / XLua 混合开发

### Q9：为什么 SLG 项目要用 Lua + C# 混合开发？

**答：** SLG 业务迭代快、策划改表和改逻辑频繁，Lua 热更成本低、开发效率高；C# 负责性能敏感部分（资源加载、网络、渲染相关、核心框架）。XLua 通过生成适配代码实现 C# 与 Lua 互调。我会把边界划清楚：C# 暴露稳定 API 给 Lua，Lua 不直接操作底层 Unity 对象，减少耦合和崩溃风险。

---

### Q10：C# 和 Lua 互相调用时要注意什么？

**答：**

1. **控制调用频率**：跨语言调用有开销，Update 里高频互调要尽量避免。
2. **对象生命周期**：Lua 持有 C# 对象引用可能导致无法 GC，注意 Dispose、Unref。
3. **类型匹配**：注意 nullable、数组、delegate 的绑定规则。
4. **异常处理**：Lua 里 C# 抛异常要能捕获，避免整段逻辑中断。
5. **架构分层**：我在项目里用 Datas 层封装数据，Business 层写 Lua 业务，减少 Lua 直接碰 Unity API。

---

## 四、架构与设计模式

### Q11：你简历里的 Business / DataHelpers / Datas 三层架构是什么？

**答：** 这是 SLG 客户端常见分层：

- **Datas**：配表数据、运行时数据模型，只负责存取和序列化。
- **DataHelpers**：数据访问助手，封装查询、缓存、本地与服务器数据同步。
- **Business**：业务逻辑层，处理 UI 流程、玩法规则、事件响应，Lua 为主。

好处是数据与逻辑分离，策划改表只影响 Datas/DataHelpers，业务改规则主要在 Business，C# 框架层稳定，便于多人协作和热更。

---

### Q12：你说用 ECS 思想重构核心模块，具体怎么做的？

**答：** 我这里的 ECS 更偏 **组件化思想**，不是严格用 Unity DOTS。做法是把原来「一个大类管所有逻辑」拆成：数据组件（位置、状态、配置 ID）+ 行为组件（移动、交互、动画）+ 系统（统一 Tick 或事件驱动）。例如大地图 PersonalObject，用 StateGraph + BehaveTree + Blackboard 分层，每种交互物只挂需要的组件，生命周期阶段（出生、选中、受惊、捕捉、销毁）由配置驱动，降低类之间强依赖，新交互物策划配表即可扩展。

---

### Q13：工厂模式 + 策略模式管理气泡体系，怎么理解？

**答：** 宠物乐园里多种气泡（任务、升级、繁荣度、宠物放置等）展示和点击逻辑不同。我用 **工厂** 根据气泡类型创建对应气泡实例，用 **策略模式** 封装每种气泡的显示规则、点击响应、刷新逻辑。新增气泡类型只需新增策略类并在工厂注册，不用改原有代码，符合开闭原则。配合对象池复用气泡 UI，减少 Instantiate 开销。

---

### Q14：状态机和行为树的区别？项目中怎么选？

**答：**

- **状态机**：适合状态清晰、转换条件明确的逻辑，如宠物动作（Idle/Walk/Eat）、场景切换（大世界 ↔ 乐园）、PersonalObject 生命周期阶段。
- **行为树**：适合 AI 决策，组合 Selector/Sequence/Condition/Action，便于策划和程序扩展节点。

在 Critter Arena 大地图里我用 **StateGraph（8 状态）管阶段 + SimpleBehaveTree 管具体行为 + Blackboard 共享数据**，状态机管「现在在什么阶段」，行为树管「这个阶段做什么」，职责清晰。

## 五、Critter Arena · 宠物乐园（重点）

### Q15：介绍一下宠物乐园系统，你负责了哪些？

**答：** 宠物乐园是 3D 成长向核心玩法，我从 0 到 1 参与并主导多版本迭代（V2/V3）。负责挂机、繁荣度、任务、升级、气泡交互、宠物放置等子系统，以及多岛屿场景、状态机切换、气泡工厂策略、宠物行为状态机、3D UI 异步加载与对象池优化。目标是让玩家在乐园里持续养成、可视化成长，同时保证场景切换和大量 UI 不卡顿。

---

### Q16：多岛屿 3D 场景系统怎么设计？为什么用常驻根场景 + 增量加载？

**答：** 乐园有 16 套主题岛屿，全部一次性加载内存和加载时间都不现实。我设计 **常驻根场景** 放公共逻辑、相机、UI 框架，**按解锁进度增量加载** 对应岛屿资源。切换时用 **游戏级状态机** 管理「大世界 ↔ 乐园」流程，配合 **云层遮罩过渡** 遮住加载过程，避免穿帮和硬切。这样首包小、内存可控，玩家解锁新岛时才加载新资源。

---

### Q17：场景切换时如何保证流畅、不穿帮？

**答：** 流程大致是：触发切换 → 播放云层遮罩动画 → 异步卸载旧岛/加载新岛 → 预加载关键资源 → 遮罩淡出 → 进入新状态。状态机严格限制切换过程中不接受重复输入。加载用 AssetBundle 异步加载，关键 3D UI 和物体走对象池预热。Profiler 看过切换峰值，把 Instantiate 峰值摊到多帧。

---

### Q18：大量 3D UI 导致卡顿，你怎么优化？

**答：**

1. **对象池**：气泡、宠物占位、常用 3D UI 预制体池化，复用而非频繁 Destroy。
2. **异步分帧创建**：不在一帧内 Instantiate 几十个 UI，用协程或分帧队列。
3. **DrawCall 控制**：合并材质、图集、减少透明叠加和 Overdraw。
4. **按需显示**：屏幕外或不可见岛屿上的 UI 不更新、不渲染。
5. **Profiler 定位**：用 Unity Profiler 看 CPU/GC，针对性优化热点。

## 六、Critter Arena · 大地图探索与 AI（重点）

### Q19：PersonalObject 交互物 AI 架构怎么设计的？

**答：** 开放世界里有 NPC、怪物、可捕获宠物、宝箱、采集点、关卡入口等 10+ 交互类型。我设计 **StateGraph（8 状态）+ SimpleBehaveTree + Blackboard** 三层：

- **StateGraph**：管生命周期阶段（出生、待机、交互、受惊、捕捉、死亡、销毁等）。
- **SimpleBehaveTree**：每个阶段下的具体行为（播放动画、转向、逃跑、抖动、渐隐等）。
- **Blackboard**：共享目标、配置、临时变量，节点间解耦。

这样新交互物主要是 **配表 + 组合行为**，策划零代码扩展。

---

### Q20：配置驱动 AI 是怎么实现的？举个例子。

**答：** 配表里定义每个生命周期阶段的行为 ID 和参数，比如「选中」阶段：转向玩家 + 播放 VFX；「受惊」阶段：播放逃跑动画 + 位移；「捕捉」阶段：抖动 + 渐隐。运行时根据对象类型读表，StateGraph 切状态，BehaveTree 执行对应节点序列。新增宝箱只需配表指定各阶段行为，不用写新 C# 类。我在 C# 侧做好节点库和扩展接口，策划在表里组合。

---

### Q21：自动寻路「前端先行计算移动」是什么意思？解决了什么问题？

**答：** 如果等服务器返回路径再动，玩家点击后角色会顿一下，体验差。我的做法是：**客户端收到点击后立即用本地寻路算法先走起来**（或先朝目标方向移动），同时发请求给服务器；服务器返回权威路径后，再做平滑校正。这样响应即时，视觉上不卡顿。要注意和服务器位置同步，避免穿墙或拉回太突兀，一般会做插值或短距离预测修正。

---

### Q22：摇杆模式和 LOD 视距开发遇到过什么难点？

**答：** 开放世界要兼顾操作方式和性能。摇杆模式要处理触摸输入、角色朝向、与自动寻路切换；LOD 要根据视距动态显示不同精度模型和特效。难点是 **模式切换时状态一致**（摇杆/点击寻路不冲突）和 **场景切换断线重连**（重连后恢复玩家位置、未完成交互状态）。我用状态机统一管理输入模式和场景状态，断线重连走服务器快照 + 本地缓存恢复。

## 七、AI 辅助研发 / OpenSpec / SDD（亮点）

### Q23：OpenSpec 规范驱动开发（SDD）是什么？你怎么用的？

**答：** SDD（Spec-Driven Development）是 **先写规范/spec，再按规范生成或校验代码** 的开发模式。OpenSpec 是我们制定的变更规范 + 模块契约，描述接口、数据结构、行为边界。流程是：需求 → 写 OpenSpec → AI 按 spec 生成代码 → 工具做一致性校验。好处是减少「理解偏差」和重复劳动，模块边界清晰，Review 也有据可依。我参与了从需求到代码的自动化生成与校验链路建设。

---

### Q24：策划案 → Figma → Unity 预制体 → AI 代码生成，全链路工作流具体怎么做？

**答：** 我参与从 0 到 1 搭建：

1. **策划案**：结构化需求文档，含功能点、交互、数据字段。
2. **Figma 交互稿**：UI 布局、状态、动效标注明确。
3. **Unity 预制体拼接**：按设计搭好 Hierarchy、挂好基础组件，形成 UI/模块模板。
4. **AI 代码生成**：把 OpenSpec + 预制体结构 + 配表约定喂给 AI，生成 Business 层 Lua 或 C# 骨架代码。
5. **人工 Review + 校验**：跑一致性检查，补边界 case 和性能优化。

我不是替代人工，而是 **提效重复劳动**，核心架构和难点仍人工把控。

---

### Q25：AI 生成的代码你怎么保证质量？

**答：**

1. OpenSpec 写清楚输入输出和边界，减少 AI 自由发挥。
2. 生成后跑 **一致性校验**（接口、命名、模块契约）。
3. 人工 Code Review，重点看生命周期、空引用、性能、与现有架构是否一致。
4. 关键模块（网络、资源、战斗）不全自动，只让 AI 生成样板代码。
5. 结合 Git 分支和 CR 流程，不直接合主分支。

## 八、Atlantis 之龙 · SLG 项目（哆咔互娱）

### Q26：PVP 回合制战斗（3 只龙）怎么实现？Stack 存后端结果是什么意思？

**答：** 这是 **服务器权威、客户端表现** 的回合制战斗。后端下发完整战斗结果序列，客户端用 **Stack** 存储每一步行为（谁攻击、技能、伤害、死亡顺序等）。表现层从 Stack 依次 Pop，驱动对应位置的龙播放动画、特效、UI 数字，直到战斗结束。这样客户端不做战斗逻辑判定，只负责演出，避免作弊，也和服务器结果一致。难点是动画时长和步骤同步，要做队列和等待动画事件回调。

---

### Q27：攻城战团队玩法怎么优化同屏几十人卡顿？

**答：**

1. **对象池** 管理所有部队预制体，复用不频繁创建销毁。
2. **控制最大显示部队数**，超出部分简化表现或用 impostor/Icon 代替。
3. **HTTP 发行为请求，Socket 同步部队信息**，网络层和表现层分离。
4. **用时间插值计算部队位置**，而不是每帧全量刷新 Transform。
5. 特效、血条按需显示，远距离降低更新频率。

---

### Q28：Unity 2017 升级到 2018 遇到过什么问题？

**答：** 主要工作包括：API 废弃替换、渲染和 Shader 兼容性、插件升级、Android/iOS 打包配置更新。具体遇到 **iOS 18 系统升级后，iOS 17 不支持游戏内 URL 跳转** 的问题，需要适配新的 WebView/URL Scheme 政策和权限配置。升级后要做全量回归，尤其关注 UI、动画、网络和资源加载。我会列升级清单，分模块验证，用 Firebase 监控崩溃定位兼容问题。

---

### Q29：Firebase 接入做了什么？

**答：** 接入 Firebase Crashlytics 监控崩溃，配置符号表上传便于定位堆栈；可能还有 Cloud Messaging 做推送通知。崩溃上报后按版本、设备、系统聚合分析，优先修高频崩溃。和网络请求优化、版本升级一起做，保证线上稳定性。

---

### Q30：3D 龙的动画和触摸交互怎么实现？

**答：** 用 **Animator 状态机** 管理 Idle、Touch、Skill 等状态。触摸时用射线或 UI 检测触摸位置，绑定不同事件名，触发动画 Event，在 Event 回调里执行命令（播放特效、音效、UI 反馈）。动画、特效、UI 解耦，策划可在状态机里配触摸响应，代码只负责分发事件。

## 九、途游 · 棋牌项目

### Q31：音效管理系统怎么设计？

**答：** 对音效 **分类**（BGM、UI 点击、出牌、胡牌等），**高频音效对象池化**，避免重复 Load。切换场景时 **卸载不用资源**，释放内存。根据用途选 **wav（短音效，低延迟）** 和 **mp3（BGM，体积小）**。播放层提供 Play(category, id) 统一接口，业务不直接 Load AudioClip，便于统一管理和静音设置。

---

### Q32：新手引导如何做到不入侵其他模块？

**答：** 用 **引导管理层** 统一调度，各业务模块只暴露「可引导节点」注册接口（按钮、面板、高亮区域），不修改模块内部逻辑。引导系统通过事件或接口获取目标 UI，加遮罩、手指、强制点击。模块无引导代码，引导结束即移除 overlay。这样新增引导步骤只改引导配置，不动业务模块。

---

### Q33：C# 重写 Lua 代码支持热更，为什么要这么做？

**答：** 部分模块 Lua 性能或维护成本不理想，或公司热更方案转向 C#（如 HybridCLR）。重写时保持 **对外接口和行为一致**，分模块迁移，先改非核心再改核心，每步可回滚。重写后走 C# 热更流程，便于统一技术栈和性能优化。我会先梳理 Lua 逻辑边界和依赖，避免改 A 坏 B。

---

### Q34：嵌套小游戏（养鱼合成、黄金矿工式捕鱼）怎么实现？

**答：** 作为独立 MiniGame 模块嵌在主项目里，有独立场景或 UI 层、独立配置（出鱼位置、概率、合成规则）。**拖动 + 碰撞检测** 判断合成或捕捉是否成功。用 **对象池** 管理鱼/道具实例，**射线检测** 鼠标/触摸方向。与主游戏通过事件或接口通信（奖励、关闭回调），不直接耦合主业务 Data。

## 十、性能优化专题

### Q35：DrawCall 是什么？你怎么优化 UI DrawCall？

**答：** DrawCall 是 CPU 通知 GPU 绘制一批图元的调用，次数过多 CPU 瓶颈。UI 优化手段：

1. **图集（Sprite Atlas）**，同图集 UI 可合批。
2. 减少 **不同材质/Shader** 混用。
3. 减少 **Mask、嵌套 Canvas**，每个 Mask 可能打断合批。
4. 静态 UI 和动态 UI **分 Canvas**，动态部分单独重建。
5. 隐藏不可见 UI 用 **CanvasGroup alpha=0 或 SetActive**，注意 SetActive 会重建布局。

我在开发中有意识控制 DrawCall，用 Profiler 和 Frame Debugger 验证。

---

### Q36：GC 是什么？Unity 里怎么减少 GC？

**答：** GC 是垃圾回收，触发时会卡顿。常见原因：每帧 new 对象、字符串拼接、LINQ、装箱、闭包捕获。避免方法：

1. 对象池复用 GameObject 和容器。
2. 缓存组件引用，避免频繁 GetComponent。
3. 用 StringBuilder 或预分配字符串。
4. 避免在 Update 里分配临时 List/数组。
5. 用 struct 代替小 class（注意拷贝成本）。

我在音效、UI、战斗表现里都用对象池和缓存，Profiler 看 GC Alloc 列定位。

---

### Q37：AssetBundle 打包和加载策略？

**答：** 按 **模块/场景/功能** 分包，控制单包大小。Manifest 管理依赖，加载时先依赖后本体。**异步加载** AsyncOperation，大资源分帧。常用资源 **缓存 AB 和 Asset**，卸载用 Unload(false) 保留实例或 Unload(true) 全卸。热更时只更新变动 AB。场景切换配合预加载和卸载，避免内存峰值。SLG 项目里岛屿、UI、特效都可独立 AB。

---

### Q38：对象池怎么实现？需要注意什么？

**答：** 预创建或按需创建对象放入池，用完 Reset 状态后归还，而不是 Destroy。注意：

1. **OnSpawn/OnDespawn** 重置位置、动画、事件监听。
2. 池大小上限，避免无限增长。
3. 不同类型分开池化。
4. 还池前取消协程、Tween、定时器。
5. 与 AB 卸载配合，避免池里对象引用已卸载资源。

我在攻城战部队、捕鱼小游戏、乐园 3D UI、音效播放里广泛使用。

---

## 十一、UI 与插件

### Q39：UGUI 和 NGUI 的区别？你更熟悉哪个？

**答：** NGUI 是老牌第三方 UI，UGUI 是 Unity 官方方案。UGUI 用 RectTransform、Canvas、EventSystem，与 Unity 工作流集成好；NGUI 在一些老项目仍在用。我两个都做过开发和动画界面，UGUI 更熟。动画方面 UGUI 可配合 DoTween、Animator，NGUI 用 Tween 组件。迁移或维护老项目时要留意渲染顺序、图集和合批差异。

---

### Q40：DoTween、Timeline、Cinemachine 分别用在什么场景？

**答：**

- **DoTween**：代码驱动 UI 动效、位移、缩放、淡入淡出，轻量灵活，我在气泡、面板弹出常用。
- **Timeline**：过场动画、技能序列、多轨道（动画、特效、音频）编排，策划可视化编辑。
- **Cinemachine**：相机跟随、震动、切换镜头，开放世界和乐园场景切换常用。

三者互补：DoTween 做小块 UI 动效，Timeline 做演出，Cinemachine 管相机。

---

## 十二、网络与协作

### Q41：HTTP 和 Socket 在项目中怎么分工？

**答：** **HTTP** 适合请求-响应式、非实时操作，如攻城战行为请求、登录、配置拉取。**Socket（TCP/UDP）** 适合实时同步，如同屏部队位置、战斗帧同步。HTTP 实现简单但实时性差；Socket 要处理重连、心跳、包序。攻城战里是 HTTP 发指令、Socket 同步状态，客户端用时间插值平滑表现。

---

### Q42：断线重连怎么处理？

**答：** 检测 Socket 断开 → 停止发送、缓存本地操作 → 尝试重连（指数退避）→ 重连成功后 **拉取服务器快照**（位置、场景、未完成交互）→ 恢复本地状态机 → 补发必要请求。开放世界里还要恢复 PersonalObject 状态、当前任务、加载中场景。要有 Loading 或遮罩避免玩家误操作。

---

### Q43：Git 多人协作你怎么用？

**答：** 功能分支开发，主分支保护，PR/MR Code Review 后合并。提交信息清晰，大功能拆小 commit。冲突多在 prefab、scene、配表，约定 **场景分工、Prefab 负责人**，改前先 pull。SLG 项目还会区分程序、策划、美术目录权限。发版打 tag，热更分支单独维护。

---

## 十三、行为树与 AI 深入

### Q44：行为树常见节点类型？

**答：**

- **Composite**：Selector（或，一个成功即成功）、Sequence（且，一个失败即失败）、Parallel。
- **Decorator**：Inverter、Repeat、Cooldown、Condition。
- **Leaf**：Action（执行动作）、Condition（检查条件）。

SimpleBehaveTree 是我们项目里的轻量实现，节点可扩展，配表挂节点 ID 和参数，Blackboard 存共享变量如 target、patrolPath、fleeDirection。

---

### Q45：Blackboard 模式是什么？

**答：** Blackboard 是 AI 共享内存，存当前目标、感知信息、配置引用、临时标志。StateGraph、BehaveTree 各节点读写 Blackboard，而不是互相直接引用，降低耦合。例如「受惊」行为从 Blackboard 读 fleeTarget 和 speed，「选中」行为写 isSelected=true。多 AI 可各有一份 Blackboard 实例。

## 十四、项目深挖（面试官常追问）

### Q46：你最有成就感的模块是哪个？为什么？

**答：** 宠物乐园从 0 到 1 和多版本迭代。一开始只有简单放置，后来扩展到 16 套主题岛、气泡体系、状态机切换、3D UI 性能优化。我主导架构设计和多子系统打通，Profiler 优化后切换卡顿明显下降，版本迭代策划需求能通过工厂+策略+配表快速扩展。完整经历需求 → 设计 → 实现 → 优化 → 迭代的全流程。

---

### Q47：你遇到的最难的技术问题是什么？怎么解决的？

**答：**（示例，结合真实经历）大地图多类型交互物扩展难、代码爆炸。我提出 StateGraph + BehaveTree + 配表驱动方案，先抽象 8 个通用生命周期状态和节点库，再让策划配表组合。难点是表现和服务器状态一致，通过前端先行寻路 + 服务器校正解决体验问题。最终新增交互物从写代码变成配表，开发效率明显提升。

---

### Q48：Profiler 你怎么用？优化流程是什么？

**答：** 打开 CPU Usage、GC Alloc、Rendering，定位高耗时函数和每帧 GC。UI 问题用 Frame Debugger 看 DrawCall 和合批。流程：**复现卡顿 → Profiler 采样 → 定位热点 → 提方案（池化、异步、合批、降频）→ 改完对比数据 → 真机验证**。我在 Critter Arena 负责资源优化和脚本工具，会写 Editor 工具辅助观测功能开销。

---

### Q49：如果让你重新设计宠物乐园，会有什么改进？

**答：**

1. 岛屿资源更早做 **Addressables** 统一地址和依赖管理。
2. 3D UI 统一 **UI 框架层**，规范池化和生命周期。
3. 场景切换状态机 **可视化调试工具**，方便查 stuck 状态。
4. 气泡体系配置 **ScriptableObject 或 Luban**，类型安全。
5. 关键路径 **自动化性能测试**，防回归。

体现思考即可，不必贬低原方案。

## 十五、软技能与综合素质

### Q51：你怎么估时和保证按时交付？

**答：** 收到需求先 **拆解子任务**（接口、UI、逻辑、联调、测试），每个估 pessimistic 时间，加 20% buffer。复杂需求先出技术方案评审，和风险点（服务器接口未定、美术资源未到）提前同步。开发中 **每日对齐进度**，block 住及时上升。在《亚特兰蒂斯之龙》里对策划需求分析拆解、准确估时是明确职责。

---

### Q52：和策划、美术意见不一致怎么办？

**答：** 先理解对方目标（体验、工期、表现），再用 **数据或 Demo** 说明技术成本和建议方案。例如性能达不到，给 Profiler 数据和建议简化方案；体验能提升但工期紧，给分阶段交付计划。以项目目标为准，不硬顶也不盲目答应，最终由主策/PM 决策。

---

### Q53：你的缺点是什么？

**答：**（真诚但安全）有时在细节优化上投入偏多，会在核心功能完成后继续抠性能。现在在改之前会先定 **性能预算和验收标准**，达到目标就转向下一优先级，平衡完美主义和交付节奏。另外英语读写可以，口语一般，技术文档阅读没问题。

---

### Q54：你为什么选择 Unity 开发？

**答：** 喜欢游戏和实时交互，Unity 生态成熟、跨平台、社区资源多，适合做手游。5 年里从棋牌到 SLG，从 UI 到 AI 和架构，越做越深入。未来希望在 **大型客户端架构、性能、工具链** 方向继续深耕，也关注 AI 辅助研发提效。
