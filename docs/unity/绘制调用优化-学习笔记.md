## 1. Draw Call 是什么，为什么要优化

一次「把东西画上屏幕」拆成两步：

1. **更新渲染状态（SetPass / bind）**  
   CPU 通过图形 API 把 shader、纹理、常量缓冲、混合模式等交给 GPU。这是最贵的一步。
2. **提交绘制（Draw）**  
   告诉 GPU：用当前状态画这份网格。

所以优化的目标通常不是「Draw 次数归零」，而是：

- 少改渲染状态（少 `SetPass`）
- 能合并的提交尽量合并
- 同样多次 Draw 时，让每次准备更便宜

Game 视图 Stats 里两个数字要分清：

| 字段 | 含义 |
| --- | --- |
| **Batches** | 提交了多少次绘制相关批次 |
| **SetPass calls** | 换了多少次渲染状态。这个往往比 Batches 更能说明 CPU 痛点 |

检查手段（官方推荐）：

- Game 视图 **Rendering Statistics** → 看 `SetPass calls`
- **Profiler → Rendering**
- **Window → Analysis → Frame Debugger**

CPU 把大量时间花在准备绘制上，才叫 CPU-bound，这时合批/SRP Batcher 才有意义。已经是 GPU 填满（过重 shader、过大分辨率、过密半透明），减 Draw Call 帮助有限。

## 2. 三种优化思路

官方把方法分成三类，不要混成「都是合批」：

| 思路 | 代表 | 做什么 |
| --- | --- | --- |
| 网格焊在一起 | Static / Dynamic Batching | 相同材质的网格拼成更大的缓冲，减少状态切换 |
| GPU 一次画很多份相同网格 | GPU Instancing / GPU Resident Drawer / BRG | 硬件实例化 |
| 不减少 Draw，但让相邻 Draw 更便宜 | **SRP Batcher** | 材质数据常驻 GPU，同 shader variant 之间少做 bind |

传统教材强调「减少 Draw Call」。SRP Batcher 的思路相反：**Draw 还可以很多，只要中间少换状态。**

---

## 3. 怎么选（Unity 6 官方建议）

官方对照表（按管线记，不要混用旧 Built-in 经验套 URP）：

| 方法 | URP | HDRP | Built-in |
| --- | --- | --- | --- |
| **SRP Batcher** | 开 | 开 | 不支持 |
| **GPU Resident Drawer** | 建议开（大场景） | 建议开 | 不支持 |
| **BatchRendererGroup API** | 一般用 Resident Drawer 即可 | 同左 | 不支持 |
| **材质上的 GPU Instancing 勾选** | 建议关（少生成额外变体） | 建议关 | 大量重复物体/灯光时开 |
| **静态批处理** | 若开了 GPU Resident Drawer / BRG，应关 | 同左 | 开 |
| **动态批处理** | 不再推荐 | HDRP 不支持 | 不再推荐 |

通用前提（不管用哪种）：

- 尽量共用材质
- 同网格只是颜色不同 → 用 **Material Variant**，不要复制出一堆独立材质
- URP/HDRP **不要**对物体设 `MaterialPropertyBlock`：它会让该 Renderer 退出 SRP Batcher

同一物体只会走一种路径，优先级：

1. SRP Batcher（若还开了静态批处理，静物可以两者一起）
2. GPU Instancing（含 GPU Resident Drawer / BRG）
3. Dynamic Batching

因此：勾了 `Batching Static` 且合批成功 → GPU Instancing 会被关掉（Inspector 会警告）。能走 Instancing 时，动态合批也会被关掉。

## 4. 动静分离 = 静态批处理 vs 动态批处理

这是第 4 节 **Batching meshes** 的核心。

合批条件的底线：

- 只支持普通 **Mesh Renderer**，**不支持 Skinned Mesh Renderer**
- 透明物体要先从后往前排序再尝试合批，所以透明比不透明难合
- 动态合批：带负缩放（镜像）的物体不能和正缩放的合在一起
- 脚本里用 `renderer.material` 会克隆材质，合批立刻断；要用 `renderer.sharedMaterial`

也可以手动 `Mesh.CombineMeshes`，但合并后不能再按原物体分别做视锥剔除。

### 4.1 静态批处理（静物）

**做什么**

- 针对**不会单独移动**的网格
- 把顶点变换到世界空间，写入共享的顶点缓冲 + 索引缓冲
- 每个缓冲最多约 **64000 顶点**，超出就再开一批
- 渲染时仍可按物体做剔除，但绘制时状态切换很少

**怎么开（构建时）**

1. `Edit → Project Settings → Player → Other Settings` → 勾 **Static Batching**
2. 选中静物 → Inspector 的 **Static Editor Flags** → 勾 **Batching Static**
3. 相同材质、满足条件的静物，打包时自动合

**运行时生成的网格**

用 `StaticBatchingUtility.Combine(...)`。运行时合批**不要求** Player 里那个 Static Batching 开关。

合完之后：

- 可以移动**整个合批根节点**
- **不能**再单独移动合批里的某一个子网格
- 代价是内存/包体变大（顶点按世界空间存了一份）

这就是「动静分离」的静：场景里的建筑、地面、不会动的道具勾 Batching Static；角色、可推箱子、会播动画的物体不要勾。

### 4.2 动态批处理（动物，官方已不推荐）

**做什么**

- 每帧在 **CPU** 上把小网格顶点变到世界空间，拼进同一次 Draw
- 粒子、Line、Trail 这类运行时几何也会走类似路径
- 投影阴影时，若阴影 pass 用的材质值相同，不同贴图的物体阴影仍可能合在一起

**限制**

- HDRP 不支持
- 网格不能超过约 **300 顶点** 或 **900 个顶点属性**（属性越多，能合的网格越少）
- 用 Lightmap 的物体必须共用同一张 lightmap 和 UV
- 多 Pass shader 只合第一个 pass（额外逐像素灯合不上）
- 现代 API 上，CPU 变换顶点的开销经常 **大于** 省下来的 Draw 开销

官方结论：**只考虑低端机；默认不要作为优化手段。** URP 上应先靠 SRP Batcher。

### 4.3 静态编辑器标志（真正的「分离」清单）

`Static Editor Flags` 不止合批，常见几项：

| 标志 | 作用 |
| --- | --- |
| **Batching Static** | 参与静态合批 |
| **Contribute GI** | 参与烘焙光照 / lightmap |
| **Occluder Static / Occludee Static** | 遮挡剔除里当遮挡物或被遮挡物 |
| **Navigation Static** | 进 NavMesh |
| **Off Mesh Link Generation** | 生成 OffMeshLink |
| **Reflection Probe Static** | 进反射探针烘焙 |

「动静分离」在工程里通常是：

- 静物：Batching Static + Contribute GI（需要烘焙时）
- 动物：全部不勾，走 SRP Batcher / Instancing
- 不要把会动的物体勾 Batching Static，否则运行时位移无效或行为异常

## 5. GPU Instancing

**做什么**：同一 mesh + 同一材质，GPU 一次 Draw 出很多份。适合树、草、箱子、碎片。Frame Debugger 里常见名字是 `Draw Mesh (instanced)`。

**要点**

- 每份实例可以有不同颜色、缩放等 per-instance 数据
- **SkinnedMeshRenderer 不支持**
- 与 **SRP Batcher 互斥**：物体若兼容 SRP Batcher，Unity **优先走 SRP Batcher**，不会走材质上的 Instancing 勾选
- 若你明确要 Instancing：要么用 `Graphics.RenderMeshInstanced`，要么主动让该 Renderer 退出 SRP Batcher（例如加 `MaterialPropertyBlock`，或换不兼容的 shader）
- Light Probe 动态物体、烘焙到**不同** lightmap 的静物，可能无法实例化在一起

URP/HDRP 下官方更倾向：普通物体交给 SRP Batcher；成千上万份相同网格再考虑 Instancing / GPU Resident Drawer，并且要 **Profiler 对比**，不要想当然。

---

## 6. SRP Batcher（URP/HDRP 主力）

官方单独成章，比静态合批更值得先看。

**核心**

- 不把网格焊成一份
- 把同 **shader variant** 的 `bind + draw` 串成一个 **SRP batch**
- 材质常量缓冲常驻 GPU；每物体矩阵等走一条专用的大缓冲更新路径
- 材质可以很多，**shader 变体要少**。变体一多，batch 会被切断

**兼容条件（自定义 shader）**

- 所有材质属性放进一个 `CBUFFER`，名字必须是 `UnityPerMaterial`
- 引擎内置矩阵等放进 `UnityPerDraw`
- URP 自带 Lit/Simple Lit/Unlit 一般已经兼容
- Inspector 选中 shader/材质可看到是否 SRP Batcher compatible

**如何开**

- 选中 URP Asset → Rendering → **SRP Batcher**
- 看不到时点右上角 ⋮ → Show All Advanced Properties

**Frame Debugger 里看什么**

- 每个 SRP Batch 会写：包含多少次 draw、用了哪些 keyword、**为什么没能接上一批**
- 常见断裂原因：`Nodes have different shaders`（变体/不同 shader）
- 很多很小的 SRP Batch = 项目 shader 变体太多

**故意退出 SRP Batcher**

只在你确认 Instancing 更划算时才做：

- 给 Renderer 加 `MaterialPropertyBlock`
- 或让 shader 不满足上面的 CBUFFER 约定

文档：[Remove SRP Batcher compatibility](https://docs.unity3d.com/6000.0/Documentation/Manual/SRPBatcher-Incompatible.html)

## 7. GPU Resident Drawer（Unity 6）

大场景自动走 `BatchRendererGroup` + GPU 实例化，省 CPU。Frame Debugger 里批次名是 **Hybrid Batch Group**。

**启用概要**

1. `Project Settings → Graphics` → Shader Stripping → **BatchRendererGroup Variants = Keep All**
2. URP Asset 打开 **SRP Batcher**
3. URP Asset 上 **GPU Resident Drawer = Instanced Drawing**
4. Universal Renderer 的 Rendering Path 设为 **Forward+**
5. 平台要支持 compute shader（不含 OpenGL ES）
6. 物体需要 **Mesh Renderer**

**和静态合批冲突**：开 Resident Drawer 时，官方建议关掉 Player 里的 **Static Batching**。

适合：场景大、很多物体共用 mesh。Scene 视图里提升往往小于真机/Play 模式。编译所有 BRG 变体会让**打包变慢、包体变大**。

---

## 8. 实操检查清单

1. 先看 Stats：`SetPass calls` 是否高，Profiler 是否 CPU Rendering 高。
2. 确认管线：URP 先保证 SRP Batcher 开着，材质兼容。
3. 静物才勾 Batching Static；会动的一律不勾。
4. 不要 `renderer.material`，用 `sharedMaterial`。
5. 少用不同 shader keyword；相同外观尽量同一材质/Material Variant。
6. 打开 Frame Debugger，点每个批次看 **break reason**。
7. Unity 6 大场景再评估 GPU Resident Drawer，并关掉静态合批后对比。
8. 动态批处理保持关，除非低端机 Profiler 证明有赚。

---

## 9. 合批为什么断（记这些就够查）

| 现象 | 常见原因 |
| --- | --- |
| 每物件单独一批 | 材质被 `renderer.material` 克隆 |
| 几乎同外观却不合 | 不同 shader、不同 keyword、不同 lightmap |
| 透明物体合不上 | 从后往前排序打断批次 |
| 勾了 Instancing 没生效 | SRP Batcher 优先；或物体是 Skinned |
| 静物勾了 Static 却移动异常 | 已进静态合批，不能单独改 Transform |
| URP 里 MaterialPropertyBlock | 退出 SRP Batcher |
| 负 Scale 的物体 | 动态合批无法与正 Scale 合并 |
| SRP Batch 又碎又多 | shader 变体太多 |
