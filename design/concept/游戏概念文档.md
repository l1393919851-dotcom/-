## 0. 文档说明

本文档是《赛博不夜城》的概念阶段（Concept Phase）产出，目标是将初版策划案中的模糊创意转化为**结构化、可评审、可实现**的设计基线。文档不涉及逐系统 GDD 级别的细节（那是下一阶段的工作），而是回答以下核心问题：

- 这个游戏的**灵魂**是什么？（核心支柱）
- 玩家在游戏中**做什么**、**感受到什么**？（MDA + 核心动词）
- 这个游戏**为谁而做**？（玩家心理学）
- 第一版**做到哪里**？（范围分层）
- 看起来**是什么样**？（视觉锚点）
- 哪些地方**可能出问题**？（风险与缓解）

所有设计决策均基于以下已知约束：
- **引擎**：Unity，已有自研框架（UI/资源/场景管理/状态机/行为树/ECS+DOTS/配置表/音效/本地化/引导系统）
- **平台**：PC
- **视角**：待定（本文档给出建议，见 §6）
- **美术风格**：2D 像素赛博朋克

## 1. 核心支柱（Design Pillars）

核心支柱是游戏的"宪法"——每一条都是**删掉之后游戏就不再是同一个游戏**的本质特征。所有后续设计决策必须向支柱对齐；任何与支柱冲突的设计都应被否决或修改。本项目确立 **4 条核心支柱**。

---

### 支柱 1：昼夜博弈（Day-Night Tension）

> **白天是棋盘，夜晚是战场。**

昼夜循环不是装饰，而是整个游戏节奏的心跳。白天，玩家是规划者——探索废墟、搜集资源、改造基地、管理幸存者，在相对安全的环境下做长线决策。夜晚，游戏切换为生存压力模式——丧尸潮涌向基地，塔防与动作战斗同时激活，玩家必须在有限时间内调度防御资源、亲自参战、保护据点。

这条支柱的核心设计含义：
- **昼夜不可跳过**，但可通过某些升级缩短/延长昼夜时长（赋予玩家有限的节奏控制权）
- **白天也不是绝对安全**——噪音过大、深入危险区域、触发特殊事件都可能引来威胁
- **夜晚的防御结果直接影响白天的资源预算**——防御战中损耗的弹药、损坏的塔、受伤的幸存者都会压缩次日的探索余量
- 所有系统（经济、建造、战斗、生存）的节奏都必须围绕昼夜循环编排

---

### 支柱 2：模块化自由（Modular Freedom）

> **不是给你一把枪，而是给你一个安装座。**

从武器到身体到基地，游戏的一切核心系统都建立在"**基座 + 模块**"的设计哲学上：
- **防御武器**不是预设成品，而是"安装器（Mount）+ 能力模块（Module）"的组合——玩家在一个武器座上自行组装不同能力的模块，创造独一无二的防御塔
- **身体改造**让玩家用零件 + 设计图逐步替换/强化自身机能，从"需要进食的普通人"进化为"以化合物驱动的赛博体"
- **基地建造**基于网格系统，玩家清理大楼后自由改造内部结构、在周边布置防御工事
- **载具**同样可改装——基础飞行车 + 附加模块（武器座/货舱/护盾）

这条支柱的核心设计含义：
- 系统设计必须采用**组合优于预设**的原则——提供少量基础元素 + 大量组合规则，而非大量预设成品
- 模块之间应有**协同与冲突**（例如：高火力模块增加噪音、高护甲模块降低移动速度），避免"全选最优"的无脑堆叠
- 模块化系统必须**可理解**——每个模块的效果一目了然，组合后的总效果需有清晰的预览界面

---

### 支柱 3：风险驱动的进化（Risk-Driven Evolution）

> **你变强的方式，就是去打比你更强的东西。**

游戏的进度推进严格遵循"**风险 → 回报 → 进化 → 更高风险**"的螺旋上升循环：
- **机械丧尸越强，掉落的设计图越稀有**——玩家想要更好的改造蓝图，就必须挑战更危险的敌人
- **身体改造是不可逆的进化分叉**——一旦改造内脏，玩家从"食物驱动"切换为"化合物驱动"，获得性能提升但承担更高的资源维护成本
- **能量核心是高风险高回报的里程碑**——要拿到能量核心，必须击败能量塔的融合怪守卫；但核心安装后扩展的安全区范围让后续探索更从容
- **噪音系统将"战术选择"转化为"风险决策"**——威力大的武器噪音大，会吸引更多丧尸；安静但低效的武器则拉长战斗时间

这条支柱的核心设计含义：
- 严格**杜绝主导策略**——不能存在一条"最优路径"让玩家无需权衡。每个选择都应有明确的代价
- 经济系统必须**避免通胀**——资源获取速率必须与消耗速率平衡，避免后期资源堆积导致所有决策失去意义
- 难度曲线必须与玩家进化曲线**同步上升**——玩家变强的同时，敌人也要变强，保持心流

---

### 支柱 4：赛博末日叙事（Cyber-Apocalypse Narrative）

> **这不是"丧尸 + 赛博朋克"的皮肤叠加，而是两者互为因果的世界。**

世界观的核心设定——"僵尸博士用5号化合物控制人类"——不是背景板的装饰文字，而是与每个系统深度咬合的设计前提：
- **机械丧尸**的存在是因为化合物技术与机械改造技术的融合——它们不是"另一种丧尸"，而是这个世界独有的产物
- **1-4号化合物**（驱动改造体的资源）与**5号化合物**（引发末日的元凶）同源——玩家用来变强的物质，正是毁灭世界的物质。这创造了内在的道德张力
- **改造师**幸存者的存在说明改造技术在末日前就已存在——博士不是发明者，而是滥用者
- **能量塔与防护罩**是赛博城市对废墟的"隔离手段"——天上之城自保，地上之人自生自灭。这构成了阶级叙事
- **4个能量塔各有一个融合怪守卫**——融合怪本身就是化合物 + 机械改造的失败/成功实验体，是博士技术的活体展示

这条支柱的核心设计含义：
- 叙事通过**环境叙事 + 物品叙事**而非长篇对话来传递——设计图上的备注、建筑内的残骸、丧尸的形态本身都在讲故事
- 世界观规则必须**可被系统化**——化合物的编号体系（1-5）、改造的层级关系、能量塔的运作逻辑都需要在 GDD 中以数据结构定义，不能自相矛盾
- 通关条件（击败博士）与世界设定**逻辑自洽**——博士的无限复活机制与化合物技术直接关联，4个能量塔的物理结构为通关路径提供了空间逻辑

## 2. MDA 分析

MDA 框架（Mechanics-Dynamics-Aesthetics）将游戏拆解为三层：**机制**（游戏的数据结构与规则）、**动态**（玩家与机制交互后涌现的行为模式）、**美学体验**（玩家获得的情感体验）。三层呈"自底向上"的因果链——机制产生动态，动态产生美学体验；但设计是从"想给玩家什么体验"（美学）倒推机制。

---

### 2.1 Mechanics（机制层）

机制是游戏的"物理定律"——规则、数据结构、数值模型。以下是本游戏的核心机制清单，按系统域分组。

#### 2.1.1 时间系统
| 机制 | 描述 |
|------|------|
| 昼夜循环 | 一个完整昼夜周期为 N 分钟（待定，建议白天 8-10 分钟 / 夜晚 5-7 分钟），可通过升级微调比例 |
| 怪物进攻周期 | 从第 X 天开始，每 N 天固定发生一次大规模丧尸潮；其余夜晚为零星骚扰 |
| 噪音触发 | 玩家行动（开枪、爆炸、建造）产生 Noise 值，在半径 R 内传播，超过阈值时吸引丧尸提前进攻 |

#### 2.1.2 空间系统
| 机制 | 描述 |
|------|------|
| 大地图 | 一张固定的城市大地图，上方为赛博之城（不可达/剧情可达），下方为废墟区（地图边界），中间为可探索城市区域 |
| 基地 | 玩家可清理一栋大楼作为主基地，内部基于网格系统改造，周边空地可布置防御工事 |
| 建筑内部 | 非废墟建筑均可进入，内部为"楼层随机拼凑"的程序化生成平面图，清理完毕后记录存储到本地，可作为据点 |
| 据点占领 | 已清理的据点若防御失败被丧尸占领，需重新清理 |
| 能量核心防护罩 | 每个能量核心安装到据点后产生半径 R 的防护罩，罩内丧尸无法进入；核心数量越多，总覆盖范围越大 |

#### 2.1.3 战斗系统
| 机制 | 描述 |
|------|------|
| 便携武器 | 玩家角色可携带赛博朋克风格武器（近战/手枪/步枪/能量武器等），每把武器有伤害、射速、噪音、弹药类型等属性 |
| 机甲 | 高级战斗装备，提供高防御与火力，但有能耗/燃料限制 |
| 载具 | 飞行汽车可快速移动并绕过无飞行能力的丧尸；可改装武器/货舱模块 |
| 防御武器组装 | "安装器（Mount）+ 模块（Module）"系统：安装器提供基座（ turret slot），玩家在其上组装不同能力模块（枪管/能量核心/弹药供弹/瞄准系统等），组合出不同性能的防御塔 |
| 防御武器类型 | 基础类：机枪塔、电塔、激光塔；进阶类由模块组合产生（如：机枪座 + 电击模块 = 电弧机枪） |

#### 2.1.4 敌人系统
| 机制 | 描述 |
|------|------|
| 普通丧尸 | 由普通人感染变异而来，低血量/低攻击/无特殊能力，掉落：金币 |
| 机械丧尸 | 经机械改造后变异的丧尸，血量/攻击/能力随等级递增，掉落：金币 + 零件 + 概率掉设计图；等级越高，设计图越稀有 |
| 飞行丧尸 | 安装了飞行模块的机械丧尸，可绕过地面防御，需防空手段应对 |
| 融合怪（Boss） | 能量塔守卫，化合物 + 机械改造的融合体，高难度，击败掉落能量核心 |
| 僵尸博士（Final Boss） | 可无限复活（用于设计图刷取），通关需先摧毁 4 个能量塔使其防护罩消失 |

#### 2.1.5 资源经济系统
| 资源 | 获取方式 | 用途 |
|------|----------|------|
| 金币（Coins） | 击杀所有丧尸、搜刮建筑 | 基础交易货币，购买基础物资/弹药/食物 |
| 零件（Parts） | 击杀机械丧尸、拆解机械废料 | 武器/防御模块制造、身体改造材料 |
| 设计图（Blueprints） | 击杀机械丧尸概率掉落、Boss 掉落 | 解锁新的武器模块、改造选项、建筑类型 |
| 食物（Food） | 搜刮、种植、幸存者烹饪 | 维持玩家（改造前）与幸存者的饱食度，提供 Buff |
| 1-4号化合物（Compounds 1-4） | 高级合成（需零件 + 设计图 + 金币） | 改造后玩家的 Buff 来源，替代食物功能，制作成本高昂 |
| 能量核心（Energy Core） | 击败能量塔融合怪守卫 | 安装到据点生成防护罩，扩展安全区 |

#### 2.1.6 生存与改造系统
| 机制 | 描述 |
|------|------|
| 饱食度（改造前） | 玩家与幸存者均有饱食度属性，随时间下降；降为 0 时持续扣血直至死亡 |
| 食物 Buff | 不同食物提供不同 Buff（如：攻击力 +10% / 移速 +5% / 生命回复），有持续时间 |
| 内脏改造（里程碑） | 改造师使用零件 + 设计图为玩家执行内脏改造后，玩家不再需要进食 |
| 化合物驱动（改造后） | 改造后玩家的 Buff 来源切换为 1-4 号化合物，每种化合物提供不同 Buff，制作成本远高于食物 |
| 幸存者食物需求 | 幸存者无法改造（或仅极少数可改造），始终需要进食，否则饿死 |

#### 2.1.7 幸存者管理系统
| 机制 | 描述 |
|------|------|
| 幸存者发现 | 在探索中可发现幸存者 NPC，对话/救援后可带回基地 |
| 幸存者角色 | 不同幸存者有不同技能倾向：建造、烹饪、战斗、医疗、科研等；分配到不同岗位影响基地效率 |
| 改造师 | 特殊智能幸存者，可执行身体改造（玩家自身），消耗零件 + 设计图 + 时间 |
| 幸存者死亡 | 幸存者在防御战中可能死亡，永久失去（Permadeath for NPCs） |

#### 2.1.8 进度系统
| 机制 | 描述 |
|------|------|
| 能量塔挑战 | 4 个能量塔分散在地图各处，每个有一个融合怪守卫，需逐个击败 |
| 能量核心安装 | 每击败一个能量塔守卫获得 1 个能量核心，安装到据点扩展防护罩范围 |
| 通关条件 | 集齐 4 个能量核心（防护罩最大），摧毁 4 个能量塔（博士防护罩消失），击败僵尸博士 |
| 僵尸博士无限复活 | 博士被击败后会复活，玩家可反复挑战以刷取高级设计图（可作为终局内容） |

### 2.2 Dynamics（动态层）

动态是玩家与机制交互后**涌现**出的行为模式——设计者不直接编写动态，而是通过机制设计来引导、抑制或放大特定的动态。以下分析本游戏预期涌现的核心动态。

#### 2.2.1 昼夜驱动的决策节律

**涌现模式**：玩家会自然形成"白天规划 → 黄昏收拢 → 夜晚防守 → 清晨盘点"的四段式行为节律。

- **白天**：玩家面临"探索 vs. 建造 vs. 搜集"的资源分配决策。探索远处的建筑有更好的战利品但占用大量白天时间；建造防御工事消耗资源但提升夜晚存活率；搜集食物是生存底线。三者争抢有限的白天时间窗口。
- **黄昏**：玩家需要决定"今晚守不守？守哪里？用什么武器？"——如果当天有大规模丧尸潮预警，玩家需要提前回基地部署；如果是零星骚扰，可以选择冒险在外过夜（有风险）。
- **夜晚**：防御战激活，玩家在"亲自参战（高风险高回报）vs. 坐镇指挥塔（依赖防御塔布局）"之间切换。噪音系统让每次开枪都成为"杀敌 vs. 引来更多敌人"的即时博弈。
- **清晨**：清点损失——弹药消耗、塔损坏、幸存者伤亡——据此调整次日计划。

**设计含义**：昼夜时长比例是关键调参变量。白天太长 → 探索无聊；夜晚太长 → 防御疲劳。需要通过 Playtest 找到甜区。

#### 2.2.2 资源稀缺性驱动的优先级博弈

**涌现模式**：多货币体系（金币/零件/设计图/食物/化合物）迫使玩家在不同进度阶段优先追逐不同资源，形成自然的"阶段感"。

- **早期**：食物 + 金币是生存底线，玩家会优先搜刮近处建筑、打普通丧尸攒钱买基础物资
- **中期**：零件 + 设计图成为瓶颈，玩家开始主动猎杀机械丧尸，风险偏好上升
- **后期**：化合物 + 能量核心成为目标，玩家需要深入高危险区域、挑战 Boss

**设计含义**：必须设计好资源转换关系（sink & faucet），确保没有一种资源在所有阶段都过剩或都稀缺。需要经济模型 spreadsheet 精确调参。

#### 2.2.3 风险回报的即时博弈

**涌现模式**：噪音系统 + 机械丧尸掉落机制创造了"打还是跑"的即时战术博弈。

- 玩家在探索建筑时遇到机械丧尸：杀掉有概率获得设计图（高回报），但战斗噪音可能引来更多丧尸（高风险）
- 玩家可以选择用安静但低效的近战武器（低噪音低效率），或用大声但高效的枪械（高噪音高效率但引来敌人）
- 这种博弈在每场遭遇战中都会发生，创造了高度可重玩的战术体验

**设计含义**：噪音值、传播半径、吸引阈值需要精确调参，确保"安静路线"和"暴力路线"都是可行策略，避免一方主导。

#### 2.2.4 模块化组装的涌现策略

**涌现模式**：模块化武器/防御系统会产生设计者未预见的有效/无效组合，形成"玩家自创 meta"。

- 玩家可能发现"电击模块 + 高射速枪管"组合出远超预期的控场效果
- 也可能组装出看似合理实际废物的组合（如"激光模块 + 散射枪管"散射后单束伤害过低）
- 这种"探索组合空间"的玩法本身就是乐趣来源（对应 Discovery 美学）

**设计含义**：需要**组合平衡矩阵**——对每对模块组合做预期效果评估，确保没有"破坏性过强"的组合（dominant strategy）。同时要保留一定的"隐藏强势组合"供玩家发现，作为奖励。

#### 2.2.5 身体改造的分叉决策

**涌现模式**：内脏改造是一个"不可逆的系统性切换"，会在玩家群体中产生"什么时候改造？要不要改造？"的策略讨论。

- 改造前：食物系统驱动，玩家需要管理食物供应链（搜刮/种植/烹饪），Buff 来自食物
- 改造后：化合物系统驱动，食物供应链可放弃（但幸存者仍需食物），Buff 来自更昂贵但更强的化合物
- 改造时机本身是策略决策——太早改造，化合物供应链跟不上；太晚改造，错失进化优势

**设计含义**：改造前后的两套系统都必须**独立可玩且有趣**，不能让其中一套明显优于另一套（否则就不是"选择"而是"正确答案"）。这是本游戏最难的设计平衡点之一。

#### 2.2.6 据点网络的扩张博弈

**涌现模式**：能量核心防护罩机制驱动玩家在地图上建立"据点网络"，形成可视化的进度推进。

- 每个能量核心扩展安全区范围，玩家可以安全地在更大范围内探索
- 玩家需要在"集中防御主基地（堆核心在一个点）"vs."分散建立前哨（核心分布在不同据点）"之间做战略选择
- 被占领的据点需要重新清理，创造了"防线被突破"的危机感

**设计含义**：防护罩的覆盖范围算法需要可视化且直觉化。多个核心的叠加规则（线性叠加？指数递减？）需要明确。

### 2.3 Aesthetics（美学体验层）

MDA 定义了 8 种美学体验（Aesthetics）。本游戏主要触达以下 6 种，按优先级排序：

| 优先级 | 美学类型 | 中文 | 在本游戏中的体现 |
|--------|----------|------|------------------|
| ★★★ | **Challenge** | 挑战 | 塔防波次的战略规划、Boss 战的战术执行、生存压力下的资源管理 |
| ★★★ | **Discovery** | 发现 | 探索程序化建筑内部、发现模块组合的隐藏强势搭配、搜集设计图解锁新内容、发掘世界观碎片 |
| ★★☆ | **Sensation** | 感官 | 像素赛博朋克的视觉冲击——霓虹灯雨夜、闪烁的全息广告、机械丧尸的金属质感、防御塔开火的火光 |
| ★★☆ | **Expression** | 表达 | 模块化武器/防御/基地/身体的自由组装，让每个玩家的"赛博体"都是独一无二的 |
| ★★☆ | **Fantasy** | 幻想 | "在赛博朋克末日废墟中从零建立据点、逐步改造自身超越人类极限、最终对抗毁灭世界的疯狂博士"——完整的英雄叙事幻想 |
| ★☆☆ | **Narrative** | 叙事 | 僵尸博士与化合物的故事弧、幸存者的遭遇、环境叙事传递的世界真相 |

未主要触达的美学：
- **Fellowship（ fellowship/社群）**：幸存者管理有社群元素，但不是核心驱动力
- **Abnegation（消遣/放空）**：本游戏节奏偏紧凑，不适合"放空"型玩家

**设计含义**：Challenge + Discovery 是双核心体验。所有系统设计都应服务于"让挑战有深度"和"让发现有惊喜"。Expression 通过模块化系统实现。Sensation 通过美术与音效实现。Narrative 以环境叙事为主，不做大量对话/过场。

## 3. 玩家心理学

### 3.1 Bartle 玩家类型分析

Richard Bartle 将多人游戏玩家分为四类。本游戏为单机游戏，但 Bartle 框架仍可用于分析"玩家在游戏中寻求什么满足感"。

```
                    ┌─────────────────┐
                    │   Achievers     │  ★★★ 主力受众
                    │   (成就者)       │  追求：进度推进、设计图收集、
                    │                 │       改造完成、Boss 击败
                    ├─────────────────┤
                    │   Explorers     │  ★★☆ 次主力受众
                    │   (探索者)       │  追求：建筑内部探索、模块组合
                    │                 │       空间、地图角落、世界观碎片
                    ├─────────────────┤
                    │   Killers       │  ★★☆ 次主力受众
                    │   (杀手型)       │  追求：战斗爽感、塔防屠杀波次、
                    │                 │       挑战高难度机械丧尸
                    ├─────────────────┤
                    │   Socializers   │  ★☆☆ 边缘受众
                    │   (社交型)       │  追求：幸存者管理、基地社区
                    │                 │       建设感（单机，社交元素有限）
```

**目标受众画像**：
- **核心玩家**：25-40 岁，喜爱生存建造（RimWorld、They Are Billions、缺氧）+ 赛博朋克美学（Cyberpunk 2077、银翼杀手）+ 塔防（Kingdom Rush、兽人必须死）的 PC 玩家
- **次核心玩家**：喜欢像素艺术 + 高自由度组装（星露谷物语的建造党、Minecraft 的红石/自动化党）
- **预期游戏时长**：主线通关 20-30 小时；完整内容（全设计图/全改造/终局刷取）40-60 小时

### 3.2 自我决定论分析（Self-Determination Theory）

SDT 认为人的内在动机由三种基本心理需求驱动：**自主性（Autonomy）、胜任感（Competence）、关联性（Relatedness）**。游戏设计应系统性地满足这三种需求。

#### 3.2.1 自主性（Autonomy）—— "我的选择被尊重"

| 设计元素 | 如何满足自主性 |
|----------|----------------|
| 模块化武器组装 | 玩家自由组合模块，没有唯一正确答案 |
| 基地建造 | 网格系统提供布局自由度 |
| 身体改造时机 | 玩家决定何时（是否）进行内脏改造 |
| 昼夜时间分配 | 玩家决定白天如何分配探索/建造/搜集 |
| 据点网络布局 | 玩家决定核心安装位置与防御策略 |
| 改造路径 | 不同设计图解锁不同改造方向 |

**风险**：自由度过高可能导致新手"选择瘫痪"。缓解：引导系统（引擎已有）提供前期方向感。

#### 3.2.2 胜任感（Competence）—— "我在变强，且挑战也在变强"

| 设计元素 | 如何满足胜任感 |
|----------|----------------|
| 难度递增的丧尸潮 | 玩家能清晰感知自己的防御体系在应对更强的敌人 |
| 设计图收集进度 | 可视化的解锁进度提供明确的成长反馈 |
| 模块组合优化 | 玩家通过试错找到更优组合时获得"我变聪明了"的满足 |
| Boss 击败里程碑 | 4 个能量塔 + 博士提供清晰的阶段性成就 |
| 据点扩张 | 防护罩范围扩大是可视化的"领地征服"反馈 |

**风险**：难度曲线过陡导致挫败，过缓导致无聊。缓解：见 3.3 心流设计。

#### 3.2.3 关联性（Relatedness）—— "我保护的幸存者不是NPC，是我的社区"

| 设计元素 | 如何满足关联性 |
|----------|----------------|
| 幸存者管理 | 每个幸存者有名字/技能/性格，不是可替换的数字 |
| 幸存者永久死亡 | 失去幸存者会带来真实的情感损失，强化保护动机 |
| 幸存者分工 | 建造者/厨师/医疗兵/改造师等角色让基地有"社区感" |
| 改造师关系 | 改造师是玩家身体进化的唯一途径，形成特殊的依赖关系 |

**风险**：单机游戏的关联性天然弱于多人游戏。缓解：幸存者需要足够的个性化（对话碎片/行为习惯/关系链），让玩家产生保护欲。

### 3.3 心流平衡设计（Flow Channel）

Csikszentmihalyi 的心流理论指出：当挑战与能力匹配时，玩家进入心流状态。挑战过高 → 焦虑；能力过高 → 无聊。

本游戏的心流曲线设计为**阶梯式上升**，每个阶梯对应一个游戏阶段：

```
挑战度
  ↑
  │                                          ╱── 通关阶段（Boss）
  │                                        ╱
  │                          ╱── 后期（能量塔挑战）
  │                        ╱    ↑
  │                      ╱      │ 玩家改造进化
  │            ╱── 中期（机械丧尸猎杀 + 改造）
  │          ╱    ↑
  │        ╱      │ 玩家获得设计图/新模块
  │  ╱── 早期（生存 + 基础防御）
  │╱    ↑
  │      │ 玩家学习基础操作
  └──────────────────────────────────────────→ 游戏时间
```

**关键心流节点设计**：

| 阶段 | 时长（预估） | 玩家能力水平 | 挑战水平 | 核心体验 |
|------|-------------|-------------|---------|---------|
| 教学期 | 0-1h | 基础操作 | 低 | 学习移动/战斗/建造/采集 |
| 早期生存 | 1-8h | 基础武器/防御 | 低-中 | 食物管理、基础塔防、探索近处建筑 |
| 中期进化 | 8-20h | 改造后/模块化武器 | 中-高 | 猎杀机械丧尸、设计图收集、模块组合实验 |
| 后期挑战 | 20-30h | 全改造/高级模块 | 高 | 能量塔挑战、融合怪 Boss、据点网络扩张 |
| 通关阶段 | 30h+ | 满配 | 极高 | 僵尸博士最终战 |
| 终局内容 | 30h+ | 满配 | 可变 | 博士无限复活刷设计图、隐藏内容 |

**心流保护机制**：
- **难度自适应**：如果玩家连续失败 N 次，可选择性降低下一波丧尸潮强度（可选难度选项，不强制）
- **安全网**：基地被攻破不会直接 Game Over，而是损失资源 + 幸存者 + 据点被占领，玩家可重建（软失败而非硬失败）
- **进度保护**：能量核心一旦获得不会丢失，确保主线进度不可逆退

## 4. 核心动词清单（Core Verbs）

动词优先法（Verb-First Design）的核心原则：**先定义玩家"做什么"，再设计系统来支撑这些动词**。动词是玩家行为的原子单位，每个动词对应一个或多个系统。

按重要性从高到低排序：

| 优先级 | 核心动词 | 英文 | 对应系统 | 设计含义 |
|--------|---------|------|---------|---------|
| 1 | **建造** | BUILD | 基地建造系统、网格系统、防御工事部署 | 玩家最频繁的交互之一；必须流畅、即时反馈 |
| 2 | **战斗** | FIGHT | 便携武器系统、机甲系统、载具战斗、塔防 | 核心爽感来源；动作手感与塔防策略并重 |
| 3 | **探索** | EXPLORE | 建筑内部程序化生成、大地图探索、据点系统 | 驱动发现体验；建筑内部设计是关键 |
| 4 | **改造** | MODIFY | 身体改造系统、武器模块组装、防御模块组装 | 核心成长路径；模块组合空间需有深度 |
| 5 | **生存** | SURVIVE | 食物/饱食度系统、化合物系统、昼夜循环 | 底层压力来源；不能太繁琐也不能太松 |
| 6 | **管理** | MANAGE | 幸存者分配、资源经济、据点网络 | 元层决策；UI 需清晰高效 |
| 7 | **搜刮** | SCAVENGE | 战利品掉落、建筑搜刮、资源采集点 | 探索的即时奖励反馈；掉落表需精心设计 |

**次要动词**（不为核心循环但增强体验）：

| 动词 | 英文 | 说明 |
|------|------|------|
| 驾驶 | DRIVE | 飞行汽车载具操作 |
| 烹饪 | COOK | 食物加工（主要由幸存者厨师执行，玩家可参与） |
| 合成 | CRAFT | 化合物/弹药/模块的制造 |
| 潜行 | SNEAK | 低噪音路线的战术选择 |

**动词关系图**：

```
        ┌──────────┐
        │  EXPLORE │←──────────────────────┐
        └────┬─────┘                       │
             │ 发现建筑/丧尸/幸存者/资源     │
             ▼                              │
     ┌──────────────┐    战利品      ┌──────┴───┐
     │    FIGHT     │──────────────→│ SCAVENGE │
     └──────┬───────┘               └────┬─────┘
            │                              │ 资源
            ▼                              ▼
     ┌──────────────┐               ┌──────────┐
     │   SURVIVE    │←──────────────│ MANAGE   │
     └──────┬───────┘    食物/资源    └────┬─────┘
            │                              │
            ▼                              ▼
     ┌──────────────┐               ┌──────────┐
     │    BUILD     │──────────────→│  MODIFY  │
     └──────────────┘  建造/防御     └──────────┘
                      模块              │ 改造
                                       ▼
                                 ┌──────────┐
                                 │ FIGHT    │←── 改造后更强
                                 │(升级循环)│    → 更深探索
                                 └──────────┘
```

**核心循环（Core Loop）一句话描述**：
> 白天探索搜刮 → 获取资源与设计图 → 建造防御与改造自身 → 夜晚抵御丧尸潮 → 战利品反馈 → 次日探索更深更远 → ... → 挑战能量塔 → ... → 击败僵尸博士

## 5. 视角建议

初版策划案未指定视角。这是一个**影响全局架构**的早期决策，必须在概念阶段确定。

### 5.1 候选方案对比

| 维度 | 俯视（Top-Down） | 侧视（Side-View） |
|------|-----------------|------------------|
| 基地建造（网格） | ★★★ 天然适配，布局清晰 | ★☆☆ 需要分层/深度处理，操作复杂 |
| 塔防（敌人路径） | ★★★ 全局视野，路径清晰 | ★★☆ 视野受限，需多层级设计 |
| 动作战斗 | ★★☆ 空间感知好但表现力弱 | ★★★ 表现力强，打击感好 |
| 建筑内部（平面） | ★★★ 天然适配"平面设计/楼层拼凑" | ★☆☆ 需侧视剖面，楼层切换复杂 |
| 大地图导航 | ★★★ 全局方向感强 | ★★☆ 需要横向滚动，方向感弱 |
| 像素美术表现力 | ★★☆ 角色小，表情细节少 | ★★★ 角色大，可做丰富动画 |
| 参考对标 | They Are Billions, RimWorld | Dead Cells, Katana ZERO |

### 5.2 建议：2D 俯视（Top-Down），带轻微等距倾斜

**理由**：

1. **建造 + 塔防是本游戏的双核心系统**，两者都强烈依赖"俯视全局视野"。侧视会让网格建造和塔防路径规划变得极其别扭，大幅增加 UX 复杂度。

2. **策划案明确提到建筑内部是"平面设计""每个楼层随机拼凑"**——这天然是俯视楼层的概念。侧视需要处理楼层剖面、Z 轴高度、角色在楼层间的切换，技术复杂度大幅上升。

3. **大地图探索**需要方向感与空间认知。俯视地图让玩家对"天上赛博之城 → 地面城市 → 地下废墟边界"的空间关系一目了然。

4. **已有引擎框架**（ECS/DOTS、行为树、状态机）在俯视 2D 下的实现最为成熟直接——俯视 2D 不需要处理 Z 轴物理、深度排序、视差滚动等复杂问题。

5. **战斗表现力的劣势可通过美术弥补**——俯视像素游戏也可以做出优秀的打击感（参考《核爆RPG》《Vampire Survivors》的爆炸效果、《They Are Billions》的群体战斗）。可通过粒子特效、屏幕震动、击杀反馈来增强表现力。

**轻微等距倾斜**（如 15-30 度俯角）可在保留俯视优势的同时增加空间纵深感，让大楼的"立体感"更好呈现。但需注意不要做成完全等距（isometric），因为等距视角下的网格坐标计算和建造放置会增加额外复杂度。

**最终建议**：纯俯视为主（0 度正俯视或极小角度），在特定场景（如大楼外观展示、Boss 战开场动画）使用轻微倾斜或透视效果增强表现力。

## 6. 范围分层（MoSCoW）

基于 Lean 评审强度（精简评审，关键节点才卡门控），范围划定务实地聚焦第一版本。以下分层基于"**砍掉 Won't Have 后仍能交付一个完整、有趣、可通关的游戏**"的原则。

### 6.1 Must Have（MVP · 必须有）

> 缺任何一条，游戏不成立。

| # | 范围项 | 说明 | 依赖系统 |
|---|--------|------|---------|
| M1 | 昼夜循环 | 白天探索 / 夜晚防御的基础节奏 | 时间系统 |

| M4 | 便携武器战斗 | 玩家角色携带武器进行实时战斗（近战 + 2-3 种枪械） | 战斗系统 |
| M5 | 普通丧尸 + 机械丧尸 | 2 种基础敌人类型 + 各自掉落表 | 敌人系统 |
| M6 | 建筑内部探索 | 程序化楼层生成 + 清理后作为据点 + 本地存储 | 空间系统 |
| M7 | 食物/生存系统 | 饱食度 + 食物 Buff（改造前阶段） | 生存系统 |
| M8 | 幸存者基础 | 发现 + 带回 + 分配基础角色（建造/烹饪） | 幸存者系统 |

## 8. 概念风险与缓解

> 诚实列出当前策划案的模糊点、缺失点、设计风险，以及建议的缓解措施。风险按严重程度排序。

---

### 风险 1：系统复杂度过高，存在认知过载风险（严重）

**描述**：策划案包含至少 8 个核心系统（建造、塔防、动作战斗、生存食物、身体改造、化合物、幸存者管理、载具），加上噪音、程序化建筑、Boss 进度等子系统。对于玩家而言，同时理解这么多系统的认知负担极高。

**MDA 红线**：认知过载（Cognitive Overload）。

**缓解措施**：
1. **阶段化引导**：利用引擎已有的引导系统（Guide System），将系统教学分散到前 2-3 小时的游戏流程中，不一次性倾倒所有系统
2. **系统依赖排序**：按 M1-M12 的 MVP 顺序，确保每个新系统在前一个系统被玩家理解后才引入
3. **UI 信息分层**：核心信息始终可见（生命/时间/快捷栏），次要信息按需展开（幸存者详情/经济总览/改造树）
4. **MVP Playtest**：MVP 阶段重点测试"玩家在前 30 分钟能否理解核心循环"，据此调整引导节奏

---

### 风险 2：身体改造的双模式切换可能产生主导策略（严重）

**描述**：改造前（食物驱动）vs. 改造后（化合物驱动）是两套不同的生存机制。如果其中一套明显优于另一套，"改造时机"就不再是策略选择而是"正确答案"。

**MDA 红线**：主导策略（Dominant Strategy）。

**缓解措施**：
1. **双模式平衡设计**：
   - 食物模式：Buff 易获取但效果较弱、饱食度下降较快但食物来源多
   - 化合物模式：Buff 效果强但制作昂贵、无饱食度问题但化合物供应链脆弱
2. **改造的代价**：改造过程本身消耗大量零件 + 稀有设计图 + 时间（改造期间玩家无法行动/防御），且改造后无法回退
3. **幸存者不变的设计约束**：即使玩家改造后不需要食物，幸存者仍需食物，玩家不能完全放弃食物供应链——这确保了改造前后的经济系统不是"替换"而是"叠加"
4. **GDD 阶段精确建模**：在生存系统 GDD 中建立食物 vs. 化合物的详细经济模型，量化对比两套模式的 ROI

---

### 风险 3：模块化武器/防御系统可能产生破坏性组合（中等）

**描述**：模块化组装的自由度意味着玩家可能发现设计者未预见的强势组合，破坏游戏平衡。

**MDA 红线**：主导策略（Dominant Strategy）。

**缓解措施**：
1. **组合平衡矩阵**：在 GDD 阶段建立所有模块两两组合的预期效果矩阵，预评估
2. **模块冲突规则**：某些模块组合有硬性冲突（如"高射速 + 高单发伤害"的模块组合受限），用规则约束而非数值微调
3. **模块负效果**：每个高收益模块附带明确的负效果（高火力 → 高噪音 + 高能耗；高护甲 → 低射程），让"全选最强"不可行
4. **Playtest + 数据监控**：MVP 阶段收集玩家实际使用的组合数据，发现异常强势组合后调整

---

### 风险 4：噪音系统规则模糊（中等）

**描述**：策划案提到"噪音触发怪物进攻"，但未定义具体规则——噪音如何产生？如何传播？如何累积？阈值是多少？

**缓解措施**：在 GDD 阶段明确噪音系统的数据模型：
- 每种武器/行动有 Noise 值（近战 5、手枪 10、步枪 20、爆炸 50、建造 5/次）
- 噪音在以声源为中心、半径 R 的圆形区域内传播（R 与 Noise 值正相关）
- 区域内的丧尸若感知到的累计 Noise 超过阈值 T，则被吸引
- 夜晚噪音传播范围更大（+50%），白天更小
- 这套规则需要在战斗系统 GDD 中精确定义并用 Playtest 验证

---

### 风险 5：程序化建筑内部的存储与重玩复杂度（中等）

**描述**："每个楼层随机拼凑，拼完以后记录存储本地"——这意味着每个建筑内部的每一层都需要持久化存储。如果地图上有数十栋可进入建筑，每栋有多个楼层，存储量和加载逻辑可能复杂。

**缓解措施**：
1. **按需生成 + 持久化**：建筑首次进入时生成楼层布局并存储；后续进入直接加载已存储的布局（不重新生成）
2. **楼层模板化**：不做纯随机，而是从预制楼层模板库中随机选取 + 随机变体（敌人分布/战利品位置），降低存储复杂度
3. **存储格式优化**：只存储结构化的布局数据（房间连接图 + 门窗位置 + 敌人生成点），不存储完整地图实例
4. **据点占领重置规则**：被占领后重新清理时，重新生成（不沿用旧布局），简化逻辑

---

### 风险 6：多货币经济体系可能失衡（中等）

**描述**：游戏有 6 种资源（金币/零件/设计图/食物/化合物/能量核心），如果获取与消耗不平衡，可能出现某些资源后期堆积无用、某些资源全程瓶颈的问题。

**MDA 红线**：经济失衡（Economy Imbalance）。

**缓解措施**：
1. **经济模型 Spreadsheet**：在 GDD 阶段建立完整的资源产出/消耗模型，按游戏阶段（早/中/后期）预估每种资源的 faucet（水龙头/产出）与 sink（水槽/消耗）
2. **资源转换机制**：设计合理的资源转换路径（如：金币 → 食物购买；零件 → 弹药制造；设计图 → 解锁后消耗零件+金币制造），让多余资源有去向
3. **阶段稀缺轮换**：确保不同阶段有不同的瓶颈资源（早期食物、中期零件、后期化合物），避免一种资源全程过剩
4. **Playtest 数据校准**：收集实际游戏数据，对比预期模型，调参校准

---

### 风险 7：僵尸博士"无限复活"机制可能造成设计矛盾（低）

**描述**：博士可无限复活用于刷设计图，但也是通关最终 Boss。如果"击败博士"既是通关条件又是可重复刷取的活动，需要明确"第一次击败 = 通关"与"后续击败 = 刷取"的区别。

**缓解措施**：
1. **分阶段设计**：
   - 第一次击败博士 = 通关动画 + 结局
   - 通关后解锁"博士实验室"终局副本，博士以更强形态无限复活，专为刷取终局设计图
2. **差异化掉落**：第一次击败给通关奖励（独特设计图/成就）；后续击败给随机高级设计图
3. **这在 Could Have 范围**：MVP 阶段不需要解决，但概念阶段需明确方向

---

### 风险 8："结局后的可玩性"待定义（低）

**描述**：策划案标注"待考虑"。如果没有终局内容，通关后玩家没有继续游玩的动力。

**缓解措施**：
1. **最小终局方案**（Could Have C1 + C6）：
   - 僵尸博士无限复活副本（刷终局设计图）
   - 无尽防守模式（丧尸波次无限递增，追求高分）
2. **NG+ 模式**（可选）：通关后开启新周目，保留改造/设计图，敌人难度提升
3. 概念阶段不做详细设计，但在 GDD 阶段需确认是否纳入 1.0 范围

---

### 风险 9：视角未定导致后续设计无锚点（低，已在本文档解决）

**描述**：策划案未指定 2D 俯视还是侧视，这是一个影响所有系统设计的基础决策。

**缓解措施**：本文档 §5 已给出建议——**2D 俯视（Top-Down）**。待主理人/用户审批后作为设计基线。

---

### 风险 10：策划案中部分设定缺乏量化定义（低）

**描述**：如"从第某天开始有怪物进攻""防护罩范围越大""机械丧尸越强力掉落越好"等描述都是定性的，缺乏具体数值。

**缓解措施**：这些在概念阶段不需要精确数值，但需要在 GDD 阶段为每个系统建立数据模型。本文档已在 MDA 机制层中标注了所有需要量化的变量，作为 GDD 阶段的工作清单。

| 7 | 安全网设计 | 基地被攻破=软失败（损失资源+据点被占），非 Game Over | 是否同意？ |

## 10. 下一步建议

概念文档审批通过后，进入 GDD 阶段，建议按以下优先级逐系统产出 GDD：

| 优先级 | 系统 | 理由 |
|--------|------|------|
| 1 | 时间系统（昼夜循环 + 怪物进攻周期 + 噪音系统） | 所有系统节奏的基石，最先定义 |
| 2 | 建造系统（网格 + 基地改造 + 防御工事） | MVP 核心交互，影响空间设计 |
| 3 | 防御武器系统（安装器 + 模块组装） | 模块化设计支柱的核心载体 |
| 4 | 战斗系统（便携武器 + 敌人 AI + 噪音） | 核心爽感来源，与防御系统联动 |
| 5 | 资源经济系统（6 种资源的产出/消耗模型） | 跨系统依赖，需尽早定义 |
| 6 | 生存与改造系统（食物/化合物/身体改造） | 双模式切换是最高设计风险点 |
| 7 | 敌人系统（普通/机械/飞行丧尸 + Boss） | 依赖战斗系统与经济系统 |
| 8 | 空间系统（大地图 + 建筑内部程序化生成 + 据点） | 依赖建造系统 |
| 9 | 幸存者系统（发现/分配/角色/改造师） | 依赖经济系统与生存系统 |
| 10 | 进度系统（能量塔/能量核心/防护罩/通关） | 依赖前面所有系统 |

每个系统 GDD 按八节结构产出：概述 / 机制 / 数据 / 公式 / 边缘情况 / UI 接口 / 依赖 / 验收标准。

## 附录 B：设计理论红线检查清单

以下红线在后续所有 GDD 设计中必须持续检查：

| # | 红线 | 检查方法 |
|---|------|---------|
| 1 | **主导策略**（Dominant Strategy） | 是否存在一条明显优于其他所有选择的路径？ |
| 2 | **经济失衡**（Economy Imbalance） | 某种资源是否在特定阶段过剩或极度稀缺？ |
| 3 | **认知过载**（Cognitive Overload） | 玩家是否需要同时关注过多系统/信息？ |
| 4 | **支柱漂移**（Pillar Drift） | 设计决策是否偏离了 4 条核心支柱？ |
