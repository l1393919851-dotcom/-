## 1. 任务概述

### 1.1 目标

产出一张**单图整合**的赛博朋克霓虹大楼关键图（Key Art / Showcase），不沿用此前"楼体底图 + 霓虹叠加层"的分层方案。**一张 PNG 同时呈现：建筑破损 + 外墙霓虹 + 窗户室内细节**。

### 1.2 用途

| 用途 | 优先级 | 说明 |
|------|--------|------|
| 美术团队内部对齐图 | ⭐⭐⭐⭐⭐ | 一图看全所有视觉决策 |
| Unity Sprite 直接使用 | ⭐⭐⭐ | 1280×720 透明背景，可直接作 Sprite 或缩放裁切 |
| 文档插图（GDD / 设计稿） | ⭐⭐⭐⭐ | 用于《游戏概念文档》《美术圣经》等插入图 |
| 营销 / 商店页素材 | ⭐⭐⭐ | 二次裁切后可作主视觉 |

### 1.3 硬性规格

| 项目 | 规格 | 说明 |
|------|------|------|
| **输出尺寸** | **1280 × 720 px** | 16:9 横向，PC 平台友好 |
| **风格** | 2D 像素风（16-bit / 32 PPU 视觉密度） | 与角色动作图、已有大楼图保持一致 |
| **背景** | **透明**（PNG-32，Alpha 通道） | 后续 Unity 做 Sprite；无水印 |
| **水印** | **无**（明确要求） | 不要 AI 工具的"图片由AI生成"水印 |
| **视角** | 俯视 3/4 视角（top-down 3/4 view） | 与美术圣经 §3.1 一致 |
| **构图对象** | **只保留建筑本体** | 不要地面网格、楼梯、外围结构、附属物 |
| **建筑高度** | 7 层（含屋顶） | 与已有规格一致 |

### 1.4 本图与已有素材的关系

| 资产 | 是否复用 | 说明 |
|------|---------|------|
| `bldg_neon_tower_base.png`（已生成 320×400） | 视觉风格参考 | 楼体结构、破损分布、屋顶设备 |
| `bldg_neon_tower_neon.png`（已生成 320×400） | 视觉风格参考 | 霓虹灯颜色、招牌位置、灯带节奏 |
| 角色动作图（已生成） | 角色 silhouette 风格 | 窗户内人物剪影应保持同一调性 |
| 美术圣经 §2 色板 | 强制约束 | 所有颜色必须来自此色板 |

## 2. 与之前拆层出图的关键差异

| 维度 | 之前（拆层方案） | 现在（整合方案） |
|------|----------------|----------------|
| **文件数** | 2 张（Base + Neon） | **1 张** |
| **画布比例** | 320×400（4:5 竖向） | **1280×720（16:9 横向）** |
| **窗户表现** | 窗户是开口，露出内部纯色 | **窗户内可见具体室内生活细节**（破旧家具、霓虹灯管、电线、吊灯、海报、人物剪影等） |
| **设计目的** | 生产用 Sprite（贴图分层） | 概念图 / 对齐图 / 多用途图 |
| **PPU 严格度** | 严格 32 PPU（4 格 = 128px） | 风格上 PPU≈32 视觉密度（不强求每像素 1/32 Unit） |
| **后期处理** | 不需要（直接合成） | **可能需要美术师后期补全窗户内景细节** |

**重要**：本图窗户"可见室内"是关键创新点。AI 生图通常在小尺寸窗口内难以稳定生成可识别的内景，建议采用以下策略：

- 提示词中**强化**窗户内景（用"dollhouse view / 透视剖面"等关键词引导）
- 单个窗户在画面中的尺寸至少 ≥ 32×32 px（1280×720 横向布局下能容纳 4-5 个/层）
- 后期由美术师在 AI 稿基础上**手工补全** 1-2 个核心窗户的内景

#### 3.4.3 外墙霓虹装饰细节

- **沿窗框走线**：每个窗户外框 1px 霓虹线（赛博紫/数据蓝交替）
- **外墙角垂直灯管**：楼体左右两侧边缘垂直灯管（赛博紫）
- **跨层霓虹管**：从 7F 到 1F 的一条主垂直霓虹管（赛博紫），类似 1970s 香港霓虹招牌美学
- **悬挂式招牌**：从 2F-3F 之间悬挂的小霓虹招牌（赛博紫 + 血光粉）
- **电缆+霓虹管缠绕**：外墙上断裂的电缆缠绕霓虹管（强化"破败感"）

### 7.1 ImageGen 透明背景实现

> **重要提示**：多数 AI 图像生成器默认不输出透明背景。**实际可用方案**：

| 方案 | 步骤 | 推荐度 |
|------|------|--------|
| **A. 后期抠图（推荐）** | 生成时背景填**单色**（建议 `#0A0E14` 暗夜黑或 `#1A1A1A`），后期用 Photoshop/GIMP 抠图替换为透明 | ⭐⭐⭐⭐⭐ |
| **B. ImageGen 直接生成透明** | 提示词强调"transparent background"，部分模型支持 | ⭐⭐⭐ |
| **C. Alpha Matting** | 用 `rembg` / `transparent-background` 等开源工具后期处理 | ⭐⭐⭐⭐ |

**推荐方案 A 的具体操作**：

1. AI 生成时背景填 `#0A0E14`（与美术圣经色板一致）
2. 输出 PNG
3. Photoshop 中：选择 → 色彩范围 → 选暗夜黑 → 删除
4. 保存为 PNG-32（保留 Alpha 通道）
5. 导入 Unity 作 Sprite 即可

1. **第 1 轮（草稿）**：用英文主提示词生成 4 张，挑选结构最接近的
2. **第 2 轮（细节）**：基于第 1 轮最佳结果，调整窗户内景的提示词强度（强化"dollhouse view"）
3. **第 3 轮（终稿）**：微调色彩饱和度、霓虹灯位置，输出终稿
4. **后期处理**：透明背景抠图 + 美术师手动补全 1-2 个核心窗户内景（如 3F 酒吧/2F 诊所）

## 8. 验收标准

AI 出图后须通过以下检查方可交付：

### 8.1 规格合规

- [ ] 分辨率严格 1280×720
- [ ] PNG-32 格式，含透明 Alpha 通道
- [ ] 无水印、无文字标签、无边框
- [ ] 仅 7 层楼 + 屋顶，无其他结构

### 8.2 视觉合规

- [ ] 俯视 3/4 视角清晰，纵深感正确（不是纯 90 度俯视）
- [ ] 像素艺术风格明显，无 3D 渲染痕迹
- [ ] 16-bit 像素密度（视觉上 PPU≈32），无平滑渐变
- [ ] 色板严格使用美术圣经 §2 的 16 种颜色

### 8.3 内容合规

- [ ] **窗户内景可见**（核心要求）：至少 50% 的窗户能辨识出至少 1-2 个室内元素
- [ ] 7 个楼层 + 屋顶结构完整可辨
- [ ] 外墙霓虹灯管装饰到位（沿窗框、垂直管、招牌、灯带）
- [ ] 霓虹色按 50% 蓝紫 / 30% 洋红 / 20% 品红 比例分布
- [ ] 破损分布在 7F/4F/2F/1F（按 §3.5 表）
- [ ] 60% 废墟 + 30% 霓虹 + 10% 强调色 比例成立

### 8.4 风格合规

- [ ] 与已有 7 层霓虹大楼图（base + neon 两版）整体风格一致
- [ ] 与角色动作图 silhouette 调性一致（窗户内人物剪影）
- [ ] 不出现"图片由AI生成"等水印
- [ ] 不出现大卫·马丁内斯本人形象

### 8.5 Unity 集成验证

- [ ] 透明背景在 Unity 中正确显示为透明
- [ ] Sprite Mode = Single
- [ ] Pixels Per Unit = 32
- [ ] Filter Mode = Point (no filter)
- [ ] 导入后无边缘锯齿/混合错误

## 9. 后期处理建议

### 9.1 透明背景处理

**优先方案**：使用 `rembg` 开源工具（命令行）

```bash
# 安装
pip install rembg[gpu]

# 处理（输出透明 PNG）
rembg i input.png output.png

# 或用 alpha matting 提高边缘精度
rembg i -a input.png output.png
```

**备选方案**：Photoshop 抠图

1. 选择 → 主体（AI 自动选择大楼）
2. 反选 → 删除背景
3. 保存为 PNG-32

### 9.2 窗户内景强化（建议手工）

AI 生图的窗户内景通常会简化或失真。建议美术师在终稿基础上**手工强化 1-2 个关键窗户**：

| 强化优先级 | 楼层 | 窗户位置 | 强化内容 |
|----------|------|---------|---------|
| ⭐⭐⭐⭐⭐ | 3F | 中央 | 赛博酒吧内部（DJ 剪影 + 霓虹酒瓶 + 舞者） |
| ⭐⭐⭐⭐ | 6F | 左侧 | 吊灯 + 沙发 + 人物剪影 |
| ⭐⭐⭐ | 2F | 中央 | 医疗床 + 医生剪影 + 义肢 |
| ⭐⭐ | 5F | 右侧 | 旧电视雪花屏 + 床 |
| ⭐ | 1F | 入口侧 | 杂货柜 + 堆叠箱 |

**强化方法**：
- 用 Aseprite / Photoshop 在原图上用 1-2 px 像素笔刷添加内景元素
- 严格使用美术圣经色板
- 完成后导出覆盖原图

### 9.3 动画版扩展（可选）

如果后续需要动画版（呼吸/脉冲/故障），建议：

- 保留本图作为静态参考
- 单独制作分层版（base + neon overlay）作 Sprite 动画
- 参考 `大厦霓虹楼_视觉规格.md` §6.3 方案 B 的 Shader 思路

## 10. 风险与待审批

### 10.1 已识别风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| **AI 难以在小窗户内生成可辨识内景** | 窗户内可能模糊成一团 | 强化"dollhouse view"关键词；后期美术师手工补全关键窗户 |
| **透明背景实现困难** | 部分 AI 工具不支持直接透明 | 用单色背景 + 后期抠图方案 A |
| **窗户数量增加导致整体复杂度飙升** | AI 容易混乱窗户位置/颜色 | 提示词中明确给出每层窗户数量和位置；分两次生成（先结构后内景） |
| **横竖构图转换（之前 320×400 → 现在 1280×720）** | 视觉比例与已有图不匹配 | 接受差异——本图是"概念对齐图"而非"生产 Sprite" |
| **窗户内景元素与角色动作图调性冲突** | 可能显得不是同一人/同一世界 | 窗户内人物剪影使用同一 silhouette 比例（头大身小 4×8px，参考大卫） |
| **PPU=32 严格性 vs 1280×720 分辨率** | 严格 PPU=32 下 1280×720 = 40×22.5 Unit，与已有 10×12.5 Unit 不符 | 本图不强求严格 PPU，仅作为"视觉密度参考" |

### 10.2 待用户审批项

1. **横竖构图选择**：从 320×400（4:5 竖向）改为 1280×720（16:9 横向）——是否接受？
2. **窗户数量翻倍**：从每层 4-6 个改为 8-12 个——是否接受更高密度？
3. **内景深度**：窗户内景是从无到有的重大视觉决策——是否需要美术总监进一步审批每层内景元素清单？
4. **后期补全范围**：建议美术师手工强化 1-2 个核心窗户，是否需要全员补全（4-5 个）？
5. **与已有 320×400 拆层图关系**：本图是替代？还是补充？是否需要在文档/UI 中并存？

### 10.3 与其他团队的协调点

| 团队 | 协调点 |
|------|--------|
| **文策渊（玩法/数值）** | 窗户内景元素与游戏功能是否对齐？例如 3F 酒吧是否有实际游戏功能？ |
| **程基岩（程序）** | 1280×720 单图 Sprite 是否符合 Unity 性能预算？是否需要分块？ |
| **阮和鸣（音频）** | 窗户内景的暗示（酒吧/诊所/杂货铺）是否影响环境音设计？ |
| **AI 生图操作员** | 是否需要提供参考图（已有 320×400 拆层图）作为 inpaint/img2img 输入？ |
