## 1. 美术支柱

三条不可妥协的视觉原则，贯穿全部资产与场景。任何偏离须经美术总监审批。

### 支柱一：霓虹与废墟的永恒张力

> **一座悬于废墟之上的赛博之城——玩家在末日中挣扎重建。**

每一个画面帧都必须同时承载"霓虹繁华"与"废墟颓败"两种视觉力量。这不是二选一的风格切换，而是同一空间内的并置与对抗：霓虹灯管残破地闪烁在布满弹孔的混凝土墙上；全息广告投射在锈蚀的铁皮屋顶上；发光的赛博义肢从腐烂的血肉中伸出。

**执行准则：**
- 每个场景至少包含一个霓虹/发光元素与一个废墟/破损元素
- 霓虹色饱和度（Saturation）≥ 70%，废墟色饱和度 ≤ 30%
- 两者之间通过中间灰度过渡，不生硬拼接
- 黑夜场景霓虹主导，白天场景废墟主导，但两者始终共存

### 支柱二：像素即信息——可读性优先

> **在像素精度与视觉丰富度之间，永远选择可读性。**

本游戏兼具生存建造、塔防战斗和楼层探索，玩家需要同时追踪大量信息：丧尸群、防御塔射程、资源点、建造网格、幸存者位置。像素艺术的职责不仅是"好看"，更是"好用"。

**执行准则：**
- 关键游戏对象（玩家、丧尸、防御塔、资源）必须在与背景对比度 ≥ 40% 的区域内可识别
- 角色 silhouette（剪影）在 32×32 像素内须可辨识身份与朝向
- UI 元素的字体最小渲染高度不低于 8px（实际像素，非缩放后）
- 像素抖动（dithering）不用于承载关键信息的区域

### 支柱三：改造即美学——玩家建造与世界的视觉融合

> **玩家的每一块建造都不是贴在废墟上的创可贴，而是对废墟的赛博改造。**

基地建造是核心玩法。玩家的建造行为在视觉上必须呈现为"将废弃建筑赛博化"的过程，而非在空地上凭空搭建。这要求建筑资产设计从一开始就考虑"废墟基底 → 改造阶段 → 完成态"的视觉递进。

**执行准则：**
- 所有可建造结构必须拥有至少三个视觉状态：废墟态、建造中、完成态
- 建造完成的建筑须保留基底材质（混凝土/砖墙）的可见痕迹，改造元素（LED 灯带/金属装甲板/全息投影器）叠加其上
- 玩家基地的霓虹光源颜色可作为势力标识色（默认青蓝色）
- 建造网格线使用低饱和度青色（`#2A3B4A` 40% 不透明度），不喧宾夺主

### 2.4 白天 vs 黑夜调色方案

#### 白天（Dawn / Day / Dusk）

白天是生存与建造的时间。视觉基调：压抑、灰暗、废墟质感主导。

| 时段 | 环境光色 | 阴影色 | 雾色 | 霓虹强度 |
|------|----------|--------|------|----------|
| **黎明**（Dawn） | `#C4B089` 暖灰黄 | `#2A2520` 深棕 | `#D4C5A0` 淡黄 | 30%（微亮） |
| **白昼**（Day） | `#A8A098` 灰白 | `#1E1E22` 冷黑灰 | `#9A9A8A` 灰黄 | 20%（几乎不可见） |
| **黄昏**（Dusk） | `#C47A4A` 暖橙红 | `#1A1020` 深紫黑 | `#7A5A4A` 橙棕 | 60%（渐亮） |

**白天调色准则：**
- 整体色温偏暖灰，饱和度压低（全局 Saturation × 0.7）
- 霓虹元素在白天几乎不发光，仅作为彩色物体存在
- 废墟纹理细节在白天最为可见，是"探索废墟"的最佳时段
- 雾效（Fog）密度中等，模拟末日雾霾，远景可见度 30-40 格

#### 黑夜（Night / Deep Night）

黑夜是战斗与危险的时间。视觉基调：霓虹主导、黑暗包裹、危险迷人。

| 时段 | 环境光色 | 阴影色 | 雾色 | 霓虹强度 |
|------|----------|--------|------|----------|
| **入夜**（Night Onset） | `#1A2030` 深蓝 | `#05080E` 近黑 | `#0F1A2A` 深蓝 | 80% |
| **深夜**（Deep Night） | `#0A0E14` 近黑 | `#000000` 纯黑 | `#080A12` 极暗 | 100%（完全发光） |
| **黎明前**（Pre-Dawn） | `#15121A` 暗紫 | `#030306` 极黑 | `#100A14` 暗紫 | 90% |

**黑夜调色准则：**
- 整体色温极冷，仅人工光源（篝火/火光/爆炸）提供暖色对比
- 霓虹光源成为主要视觉引导——玩家本能地被光源吸引
- 黑暗区域不使用纯黑（`#000000`），最低使用 `#05080E` 以保留像素可读性
- 黑夜是丧尸潮时段，血光粉 `#FF003C` 作为危险信号在此时段最为醒目
- 雾效密度提高（Fog Density × 1.5），模拟黑暗中的未知恐惧

### 2.5 色彩使用规则

1. **60-30-10 法则**：每个场景中废墟色系（灰/棕/黑）占 60%，霓虹/科技色系占 30%，强调色（红/黄/绿）占 10%
2. **不要使用未在色板中定义的纯色**——所有自定义颜色须从色板色混合或降低饱和度后取得
3. **赛博紫 `#B026FF` 是品牌色**——用于标题画面、核心 UI 框架、能量系统图标，不随意散布在环境中
4. **血光粉 `#FF003C` 严格限定用途**——仅用于危险/警报/丧尸相关元素，不用于装饰
5. **渐变色仅在天空盒和雾效中使用**——Sprite 资产不使用渐变，保持像素硬边

## 3. 像素规格

### 3.1 视角建议：俯视 3/4 视角（Top-Down 3/4 View）

**建议采用俯视 3/4 视角**（类似 Hyper Light Drifter / Stardew Valley 的俯视带轻微纵深视角），而非纯侧视。理由如下：

| 评估维度 | 俯视 3/4 视角 | 纯侧视（Side-Scroll） |
|----------|-------------|---------------------|
| 格子建造 | ✅ 天然适配网格，俯视即建造面 | ❌ 侧视难以展示平面布局 |
| 塔防战斗 | ✅ 可见四面来敌，射程清晰 | ❌ 仅可见左右来敌 |
| 建筑内部探索 | ✅ 俯视可看全房间布局 | ❌ 需要分层渲染，复杂度高 |
| 多楼层感 | ✅ 通过 Y 轴偏移和遮罩模拟 | ❌ 天然适合，但与建造冲突 |
| 赛博朋克氛围 | ✅ 霓虹地面投影效果好 | ✅ 霓虹轮廓效果好 |
| 参考对标 | Hyper Light Drifter, Stardew | Dead Cells, Katana ZERO |

**结论：俯视 3/4 视角更适合本游戏的核心玩法组合**（建造 + 塔防 + 探索）。侧视虽在战斗手感上有优势（参考 Dead Cells），但会严重限制建造和塔防的空间表达。

**技术实现：**
- 摄像机类型：Orthographic（正交投影）
- 摄像机角度：Y 轴无旋转，Sprite 通过自身的 3/4 视角绘制模拟纵深
- 不使用 3D 模型旋转，纯 2D Sprite 表现

### 3.2 像素密度与 PPU 标准

**Pixels Per Unit（PPU）= 32**

即 1 Unity Unit = 32 像素。这是本游戏所有像素资产的基础度量单位。

| 对象类型 | 像素尺寸（px） | 占用格子数 | 说明 |
|----------|---------------|-----------|------|
| **基础 Tile** | 16 × 16 | 0.5 格 | 地面/墙面最小拼接单元 |
| **建造格子** | 32 × 32 | 1 格 | 玩家建造的基本单位 |
| **小型道具** | 16 × 16 ~ 32 × 32 | 0.5 ~ 1 格 | 路障、资源箱、灯具 |
| **玩家角色** | 32 × 48（站立框） | 1 × 1.5 格 | 含头部上方留白，碰撞体 32×32 |
| **普通丧尸** | 32 × 48 | 1 × 1.5 格 | 与玩家同等比例 |
| **机械丧尸** | 48 × 64 | 1.5 × 2 格 | 比普通丧尸大，有压迫感 |
| **BOSS** | 96 × 128 ~ 128 × 160 | 3 × 4 ~ 4 × 5 格 | 屏幕占比 15%-25% |
| **防御塔（小型）** | 32 × 48 | 1 × 1.5 格 | 机枪塔、电塔 |
| **防御塔（大型）** | 48 × 80 | 1.5 × 2.5 格 | 激光塔、自定义武器 |
| **建筑外墙** | 32 × 32 per segment | 1 格 per segment | 按格子拼接 |
| **飞行汽车** | 64 × 32 | 2 × 1 格 | 背景层动态元素 |

### 3.3 摄像机设置

| 参数 | 值 | 说明 |
|------|-----|------|
| Projection | Orthographic | 正交投影，无透视变形 |
| Orthographic Size | 8.5 | 即垂直方向可见 17 格（17 × 32px = 544px），适配 16:9 |
| PPU | 32 | 全局统一 |
| Pixel Perfect | 启用 | 使用 Unity 2D Pixel Perfect 包 |
| Snap Camera to Pixel Grid | 启用 | 消除亚像素抖动 |
| Reference Resolution | 640 × 360 | 基准渲染分辨率（16:9） |
| Upscale Filter Texture | Point（无滤波） | 保持像素硬边 |

**分辨率缩放策略：**
- 基准内部分辨率：640 × 360（16:9 最小整数倍适配 1920×1080）
- 档位 1（低）：640 × 360 → 整数缩放至目标分辨率
- 档位 2（中）：960 × 540 → 整数缩放
- 档位 3（高）：1280 × 720 → 整数缩放
- 档位 4（超高）：1920 × 1080 → 原生或整数缩放
- 非整数倍时使用 Letterbox（黑边），不使用拉伸

### 3.4 像素绘制规则

1. **统一像素密度**：所有 Sprite 必须在 32 PPU 下绘制，不允许混用不同 PPU 的资产
2. **禁止亚像素**：所有精灵移动、摄像机移动必须 snap 到整数像素位置
3. **描边规则**：角色使用 1px 外描边（使用比最暗色再暗一级的颜色），建筑和道具不强制描边
4. **抗锯齿**：全局关闭 MSAA，Sprite 使用 Point Filter，UI 文字使用 Pixel-Perfect 字体
5. **缩放限制**：Sprite 仅允许整数倍缩放（×1, ×2, ×3...），禁止非整数缩放

## 4. 角色设计方向

### 4.1 玩家角色（Survivor Commander）

**视觉概念**：一个在末日中学会赛博改造的幸存者领袖。不是超级英雄，而是被逼进化的人类。

| 属性 | 规格 |
|------|------|
| 像素尺寸 | 32 × 48（站立框，含上方留白） |
| 碰撞体 | 32 × 32 |
| 色板 | 以混凝土灰为基底服装，数据蓝 `#00F0FF` 为义肢/LED 标识 |
| 剪影特征 | 右臂赛博义肢（比左臂粗，有发光关节），背部背包/工具带 |
| 朝向 | 4 方向（上/下/左/右），每个方向独立 Sprite |
| 动画帧 | 见 §8.4 |

**视觉细节清单：**
- 面部：防毒面罩或半面罩，仅露出一只发蓝光的赛博眼
- 服装：破损的军用外套，内搭科技背心，露出义体接口
- 右臂：金属义肢，关节处发出数据蓝光，可替换武器模块
- 背部：工具背包，侧面挂有建造蓝图卷轴
- 腰部：弹药带 + 手电筒
- 脚部：加固军靴，左腿有外骨骼支架

### 4.2 普通丧尸（Common Zombie）

**视觉概念**：曾经的普通市民，感染后失去人性。衣衫褴褛，肢体变形，但保留"人"的轮廓以制造不适感。

| 属性 | 规格 |
|------|------|
| 像素尺寸 | 32 × 48 |
| 碰撞体 | 32 × 32 |
| 色板 | 以暗灰绿 `#3A4A3A` 为皮肤色，铁锈棕 `#7A4E2D` 为衣物色 |
| 剪影特征 | 前倾驼背，一臂前伸（经典丧尸姿势），头部歪斜 |
| 朝向 | 4 方向 |
| 变体 | 3 种服装变体（市民/工人/安保），共用骨骼动画 |

**视觉细节：**
- 皮肤：灰绿色，有暗紫色感染纹路（血光粉 `#FF003C` 低饱和度版）
- 眼睛：空洞或发出暗红色微光（`#8A0020`）
- 衣物：根据变体不同——市民穿破损休闲服，工人穿反光背心残片，安保穿防弹衣碎片
- 伤口：可见的咬痕/撕裂处，使用锈血红 `#5C1A1A`
- 动画特征：行走时拖拽一条腿，攻击时前扑

### 4.3 机械丧尸（Cyber-Mech Zombie）

**视觉概念**：被赛博改造过的人类变异为丧尸——肉体与机械的扭曲融合。这是本游戏的标志性敌人。

| 属性 | 规格 |
|------|------|
| 像素尺寸 | 48 × 64 |
| 碰撞体 | 48 × 48 |
| 色板 | 金属灰 `#4A5055` 为机械部分，暗灰绿 `#3A4A3A` 为残存肉体，毒雾绿 `#39FF14` 为能量泄漏 |
| 剪影特征 | 体型明显大于普通丧尸，不对称——一侧有大型机械臂或胸腔嵌入能量核心 |
| 朝向 | 4 方向 |
| 变体 | 3 种改造类型（战斗型/护甲型/射弹型） |

**视觉细节：**
- 机械部分：暴露的金属骨架，关节处有液压管，发出低沉的机械运转声
- 能量核心：胸腔或头部嵌入不稳定能量核心，发出毒雾绿 `#39FF14` 脉冲光
- 肉体部分：仅存少量灰绿色皮肉缠绕在金属骨架上，有电火花间歇闪烁
- 警示灯：头部或肩部有闪烁的红色警示灯（血光粉 `#FF003C` 脉冲）
- 动画特征：行走时金属关节发出火花，攻击时机械臂加速冲撞

**变体视觉区分：**
| 变体 | 标识特征 | 体型差异 |
|------|---------|---------|
| 战斗型（Brute） | 右臂为大型液压拳，胸口装甲板 | 宽体，肩部更宽 |
| 护甲型（Juggernaut） | 全身覆盖锈蚀金属装甲板，仅腹部弱点 | 高体，略矮 |
| 射弹型（Rifle） | 背部嵌入改装能量炮，发射毒绿光弹 | 标准体，背部突出 |

### 4.4 幸存者 NPC（Survivor NPCs）

**视觉概念**：被玩家营救并招募的普通幸存者。他们代表"人性尚存"。

| 属性 | 规格 |
|------|------|
| 像素尺寸 | 32 × 48 |
| 碰撞体 | 32 × 32 |
| 色板 | 以暖色为主（暖灯橙/骨白），代表"正常人类"的温暖感 |
| 剪影特征 | 直立行走，无前倾，体型比玩家略瘦小 |

## 5. 环境设计方向

### 5.1 世界宏观结构

游戏世界分为两个垂直层：

```
        ┌─────────────────────────┐
        │    ☁ 赛博之城（天空层）    │  ← 远景/背景，不可到达
        │    ╔═════════════════╗   │
        │    ║  悬浮赛博都市    ║   │  ← 霓虹灯光从上方投射
        │    ╚═════════════════╝   │
        │         ▼ ▼ ▼            │  ← 光柱/能量连接
   ─────┼─────────────────────────┼─────  ← 地平线
        │                          │
        │   ▓▓▓ ▓▓▓ ▓▓▓ ▓▓▓      │  ← 废墟层（游戏区域）
        │   ▓██▓ ▓██▓ ▓██▓ ▓██▓   │
        │   ▓██▓ ▓██▓ ▓██▓ ▓██▓   │  ← 玩家在此建造与生存
        │                          │
        └─────────────────────────┘
```

- **天空层（赛博之城）**：始终作为远景出现在画面上方，霓虹璀璨，代表"失落的文明"
- **废墟层（游戏区域）**：玩家活动的地面层，曾经是赛博之城的地基/下层区，现已沦为废墟
- **能量连接**：赛博之城与废墟之间有能量光柱/电缆连接，视觉上暗示"上面的城市仍在抽取下方的能源"

### 5.2 环境区块类型

#### 5.2.1 废墟城区（Ruins District）

**视觉概念**：曾经繁华的赛博城区下层，现在满目疮痍。是游戏的初始区域。

- **地面**：龟裂的混凝土路面，缝隙中长出杂草，散落碎玻璃和金属碎片
- **建筑**：半倒塌的楼房残骸，露出钢筋骨架，窗户破碎，墙面有褪色的赛博涂鸦
- **装饰**：废弃的飞行汽车残骸（可作为资源点），倒塌的全息广告牌（仍间歇性闪烁），锈蚀的路灯
- **植被**：杂草从裂缝中生长，藤蔓攀爬在建筑表面——自然正在回收城市
- **光源**：仅来自赛博之城的反射光和间歇性故障的路灯
- **色温**：白天灰黄压抑，黑夜中只有偶尔的故障电火花

#### 5.2.2 赛博城区残骸（Cyber District Remains）

**视觉概念**：曾经赛博化程度更高的区域，科技残骸更多，危险也更多。

- **地面**：金属格栅路面，下方可见管道和电缆，部分区域发出微光
- **建筑**：保留了更多赛博改造痕迹的建筑——LED 灯带残骸、全息投影器底座、金属装甲墙面
- **装饰**：废弃的自动贩卖机（部分仍有电力），能量管线（发出蜂鸣声），服务器机柜堆
- **危险元素**：不稳定能量泄漏点（毒雾绿发光区域），坍塌的金属天桥
- **光源**：残存的赛博照明系统仍部分运作，霓虹色彩更丰富
- **色温**：偏冷蓝，霓虹残留更密集

#### 5.2.3 建筑内部（Building Interior）

**视觉概念**：玩家进入大楼进行楼层探索时所见。每层随机拼凑，布局不同。

- **视角切换**：进入建筑时摄像机 zoom in（Orthographic Size 从 8.5 缩至 5.5），聚焦室内
- **墙体**：室内墙面分层渲染——后墙（最暗）、侧墙（中灰）、前墙（可被角色遮挡时半透明化）
- **地板**：不同楼层有不同主题——办公室（地毯+办公桌残骸）、住宅（瓷砖+家具残骸）、实验室（金属地板+设备残骸）、工厂（格栅地面+管道）
- **天花板光源**：残存的日光灯管（冷白光）或应急灯（暗红光），部分闪烁
- **门**：分为普通门、安全门（需破解/钥匙）、卷帘门（需力量/工具）
- **楼层过渡**：楼梯/电梯井作为楼层间过渡场景

**楼层随机拼凑视觉规则：**
- 每层由预设房间模块（Room Module）随机拼接组成
- 每个模块为 5×5 格（160×160 px），含入口/出口连接点
- 模块间通过门/洞口连接，墙体遮挡未连接方向
- 模块按主题分组：办公模块组、住宅模块组、实验模块组、工厂模块组

#### 5.2.4 玩家基地（Player Base — 改造后的大楼）

**视觉概念**：玩家清理并改造后的大楼。这是"改造即美学"支柱的主要体现。

**改造阶段视觉递进：**

| 阶段 | 基底状态 | 改造元素 | 霓虹强度 |
|------|---------|---------|---------|
| **0 — 废墟态** | 完全废墟，不可进入 | 无 | 0% |
| **1 — 清理态** | 清除内部瓦砾，结构可见 | 无 | 0% |
| **2 — 基础改造** | 墙体修复，基本设施安装 | 简易 LED 灯带（数据蓝），铁皮封板 | 20% |
| **3 — 功能改造** | 分区完成（居住/生产/防御） | 全息投影牌，能量管线外露，金属装甲墙面 | 50% |
| **4 — 完全赛博化** | 外观完全赛博化 | 全息广告牌（自定义内容），能量罩接口，LED 灯带全覆盖，外墙装甲完成 | 80% |

**基地视觉元素：**
- **LED 灯带**：沿建筑外墙顶部和窗户边缘铺设，数据蓝 `#00F0FF` 发光，可作为玩家势力标识
- **全息投影器**：屋顶安装，投射全息标识（玩家可自定义），赛博紫 `#B026FF`
- **外挂装甲板**：金属板焊接在外墙上，带有焊缝纹理和警示黄 `#FFD700` 标识线
- **能量管线**：外露的管道和电缆连接各功能区，有流动的光效（数据蓝脉冲）
- **防御工事**：窗户被封堵并安装射击孔，门口设有路障和检查点

### 5.3 背景层与视差

游戏使用多层视差滚动（Parallax）营造深度：

| 层级 | 内容 | 视差系数 | 说明 |
|------|------|---------|------|
| Layer 0（最远） | 赛博之城（天空层） | 0.1 | 始终在画面上方，几乎不动 |
| Layer 1 | 远景废墟天际线 | 0.3 | 模糊的楼群剪影 |
| Layer 2 | 中景废墟建筑 | 0.6 | 半透明的远景建筑 |
| Layer 3（游戏层） | 地面 + 可交互建筑 + 角色 | 1.0 | 主游戏层 |
| Layer 4（前景） | 前景遮罩（柱子/檐口/植被） | 1.3 | 偶尔遮挡画面的前景元素 |
| Layer 5（最前） | 雾气/粒子/天气 | 1.5 | 大气效果层 |

### 6.4 字体方向

**像素字体，禁止使用矢量字体。**

| 用途 | 字体推荐 | 渲染尺寸 | 说明 |
|------|---------|---------|------|
| HUD 数字 | Press Start 2P 或自绘像素字体 | 8px 实际像素 | 等宽数字 |
| UI 标签 | 自绘 5×7 像素字体 | 8-10px | 统一项目字体 |
| 对话文本 | 自绘可变宽像素字体 | 10-12px | 支持中文 |

- 数字和英文字母使用 5×7 或 8×8 栅格
- 不混用不同字体的像素密度

### 6.5 面板与窗口设计

- **面板材质**：暗色半透明背景（80% 不透明度暗夜黑），1px 数据蓝边框，内部有水平扫描线纹理（间距 2px，5% 不透明度白色）

- **分割线**：1px 数据蓝线，两端有 2px 的赛博紫短装饰线
- **按钮**：默认态为暗灰填充 + 数据蓝边框；悬停态边框变亮 + 微微发光；按下态颜色反转
- **滑块**：轨道为暗灰，填充部分为数据蓝，滑块为赛博紫方块
- **复选框**：未选为空方框，选中为方框内填数据蓝 + 像素对勾

## 7. 光照与氛围

### 7.1 昼夜循环光照方案

Unity URP 2D 光照系统，使用 2D Light + Light 2D 组件。

#### 7.1.1 光照参数曲线

| 时段 | 环境光强度 | 环境光色 | 主光源（赛博之城投射光） | 阴影强度 | 雾密度 |
|------|-----------|---------|------------------------|---------|--------|
| 黎明 (05:00-07:00) | 0.4 | `#C4B089` 暖灰黄 | 0.2 `#8FA8C8` 冷蓝白 | 0.6 | 0.03 |
| 白昼 (07:00-17:00) | 0.7 | `#A8A098` 灰白 | 0.1 | 0.8 | 0.05 |
| 黄昏 (17:00-19:00) | 0.5 | `#C47A4A` 暖橙红 | 0.3 `#B026FF` 赛博紫 | 0.7 | 0.04 |
| 入夜 (19:00-21:00) | 0.2 | `#1A2030` 深蓝 | 0.5 `#00F0FF` 数据蓝 | 0.5 | 0.06 |
| 深夜 (21:00-04:00) | 0.08 | `#0A0E14` 近黑 | 0.4 `#8FA8C8` 冷蓝白 | 0.3 | 0.08 |
| 黎明前 (04:00-05:00) | 0.1 | `#15121A` 暗紫 | 0.3 `#B026FF` 赛博紫 | 0.4 | 0.07 |

**URP 2D 光照配置：**
- 使用 URP 2D Renderer + 2D Light 组件
- 环境光使用 Global Light 2D（Composite 模式）
- 霓虹光源使用 Freeform Light 2D 或 Point Light 2D
- 阴影使用 Shadow Caster 2D 组件挂载在建筑 Sprite 上

#### 7.1.2 赛博之城投射光

天空层的赛博之城作为"上方主光源"概念存在：
- 白天：赛博之城几乎不可见（被日光掩盖），仅作为远景剪影
- 黄昏：赛博之城开始发光，紫色光晕从画面上方投射下来
- 深夜：赛博之城成为最亮光源，霓虹光柱穿透雾气投射到废墟层，形成戏剧性的顶光效果
- 投射光方向：从上向下（Y 轴负方向），角度可微微偏移以增加变化

### 7.2 霓虹光源表现

#### 7.2.1 霓虹灯管（Neon Tube）

- **Light 类型**：Point Light 2D，半径 2-4 格
- **颜色**：赛博紫 `#B026FF` 或数据蓝 `#00F0FF`
- **强度**：1.5 - 2.5（深夜时增强至 3.0）
- **表现**：Sprite 本体为发光灯管像素画 + Point Light 产生地面光晕
- **故障效果**：间歇性闪烁（Random flicker），10% 的灯管为故障态（闪烁频率 0.5-2Hz）

#### 7.2.2 全息投影（Hologram）

- **Light 类型**：Freeform Light 2D（匹配投影形状）
- **颜色**：数据蓝 `#00F0FF` 50% 透明度
- **强度**：0.8 - 1.2
- **表现**：
  - Sprite 使用半透明叠加渲染（Additive Blend）
  - 水平扫描线纹理叠加（每 4px 一条线，10% 透明度白色）
  - 轻微的 Y 轴抖动（±1px，模拟全息不稳）
  - 底部有地面积光效果

#### 7.2.3 LED 灯带（LED Strip）

- **Light 类型**：Sprite 自发光（不单独使用 Light 2D，优化性能）
- **颜色**：数据蓝 `#00F0FF`（玩家基地）/ 赛博紫 `#B026FF`（装饰）
- **表现**：建筑边缘的连续像素发光带，使用 Emission Map 或 Sprite 自发光色
- **呼吸效果**：缓慢亮度脉冲（2-4 秒周期，亮度 70%-100%）

### 7.3 VFX 方向

#### 7.3.1 防护罩（Energy Shield）

- **外观**：覆盖玩家基地的半球形能量罩
- **颜色**：数据蓝 `#00F0FF` 30% 透明度，边缘 60% 透明度
- **效果**：
  - 六边形网格纹理（Hexagon Grid）覆盖整个罩面
  - 网格线缓慢流动（UV 滚动）
  - 受到攻击时受击点产生波纹涟漪（Ripple）
  - 罩体边缘有能量粒子飘散
- **性能**：使用 Shader 实现，不用粒子系统模拟罩体本身

#### 7.3.2 能量塔（Energy Tower）

- **外观**：高耸的赛博能量发射塔，顶端有大型能量核心
- **颜色**：核心为毒雾绿 `#39FF14` → 白色渐变；光柱为冷绿白 `#A8FFD0`
- **效果**：
  - 顶端核心持续脉冲发光（1-2 秒周期）
  - 向上发射的能量光柱（垂直光束 + 缓慢旋转）
  - 底部有能量积聚的地面光圈
  - 周围有能量粒子飘浮上升
- **影响范围**：以塔为圆心，半径可视化的半透明绿色光圈地面投影

## 8. 资产制作规范

### 8.1 Sprite 切片规范

**图集（Sprite Atlas）组织原则：** 按功能模块分图集，单张图集不超过 2048×2048。

| 图集名称 | 最大尺寸 | 包含内容 | 切片方式 |
|---------|---------|---------|---------|
| `atlas_characters` | 2048×2048 | 玩家、NPC、丧尸的所有方向+动画帧 | Multiple Sprite 切片 |
| `atlas_tiles_ground` | 1024×1024 | 地面 Tile（16×16 per tile） | Grid 切片 16×16 |
| `atlas_tiles_wall` | 1024×1024 | 墙面 Tile（16×16 per tile） | Grid 切片 16×16 |
| `atlas_buildings` | 2048×2048 | 建筑 Sprite（多尺寸） | Multiple Sprite 切片 |
| `atlas_props` | 1024×1024 | 道具/装饰物（多尺寸） | Multiple Sprite 切片 |
| `atlas_effects` | 1024×1024 | VFX Sprite | Multiple Sprite 切片 |
| `atlas_ui` | 1024×1024 | UI 图标/面板元素 | Grid/Multiple 切片 |

**切片规则：**
1. 所有 Sprite 边缘留 1px 透明边距（防止采样溢出）
2. 同一动画序列的帧必须在图集中水平连续排列
3. 切片 Pivot 统一设置：
   - 角色：Bottom Center（底部居中）
   - Tile：Center（居中）
   - 道具：Center
   - UI 图标：Center
4. 图集压缩格式：PC 平台使用 RGBA 32-bit（不压缩，保持像素精度），移动端降级至 ASTC 6×6

### 8.2 Tilemap 规格

| 属性 | 值 | 说明 |
|------|-----|------|
| Tile 尺寸 | 16 × 16 px | 最小拼接单元 |
| Cell Size | 0.5 × 0.5 Unit | 16px / 32PPU = 0.5 Unit |
| 建造格子 | 2 × 2 Tile = 32 × 32 px | 玩家建造单位 |
| Tilemap Layer 顺序 | Ground → GroundDetail → Wall → WallDetail → Object → Overlay | 从下到上渲染 |
| Rule Tile | 使用 Unity Rule Tile 自动拼接 | 减少手工拼接工作量 |

**Tilemap 分层：**

| 层名 | 用途 | 排序层级（Sorting Layer） | Order in Layer |
|------|------|------------------------|----------------|
| Ground | 地面基础纹理 | Ground | 0 |
| GroundDecal | 地面装饰（血迹/裂缝/碎片） | Ground | 1 |
| Wall | 墙体 | Wall | 0 |
| WallDecal | 墙面装饰（涂鸦/海报/破损） | Wall | 1 |
| Object | 可交互物体（道具/家具/门） | Object | 按Y轴排序 |
| Character | 角色/敌人/NPC | Character | 按Y轴排序 |
| Effect | VFX/粒子 | Effect | 0 |
| Overlay | 前景遮罩（柱子/檐口） | Overlay | 0 |
| UI | 游戏内 UI（建造网格等） | UI | 0 |

**Y 轴排序规则：** Character 和 Object 层使用 `Sort by Y`，即 Sprite 的 Y 坐标越大（越靠下），渲染层级越高（覆盖在上方），模拟俯视下的前后遮挡关系。

## 9. 可访问性

### 9.1 可访问性分级

本游戏目标可访问性分级：**Standard（标准级）**

| 分级 | 标准 | 本游戏目标 |
|------|------|-----------|
| Basic（基础级） | 满足最低可玩性 | — |
| **Standard（标准级）** | 满足大部分常见障碍的基本可用性 | ✅ |
| Comprehensive（全面级） | 深度适配，覆盖罕见障碍 | — |
| Exemplary（标杆级） | 行业最佳实践，可获奖 | — |

### 9.2 像素游戏特有可读性问题

| 问题 | 影响 | 对策 |
|------|------|------|
| **小像素导致细节不可辨** | 视力障碍玩家无法辨识角色/物品 | 提供缩放选项（§9.3.1）；关键信息不依赖微观像素细节 |
| **像素色彩混色产生歧义** | 色盲玩家难以区分相似色块 | 色盲模式（§9.3.2）；关键信息不仅靠颜色区分 |
| **高频闪烁引发光敏性癫痫** | 光敏性癫痫玩家健康风险 | 闪烁频率 ≤ 3Hz（§9.3.6）；提供关闭闪烁选项 |
| **像素文字小尺寸不可读** | 视力障碍玩家无法阅读 UI | 文字缩放选项；关键文字最小渲染高度 8px |
| **粒子噪音干扰** | 注意力障碍/ADHD 玩家被干扰 | 可关闭装饰性粒子（§9.3.5） |
| **快速动画导致运动不适** | 前庭敏感玩家不适 | 动画速度可调；可关闭镜头抖动 |

### 9.3 可访问性特性矩阵

#### 9.3.1 画面缩放（Zoom）

| 选项 | 值 | 说明 |
|------|-----|------|
| 画面缩放 | 0.8x / 1.0x（默认）/ 1.2x / 1.5x | 调整 Orthographic Size，1.2x 以上会有画面裁剪 |
| UI 缩放 | 0.9x / 1.0x（默认）/ 1.1x / 1.25x | 独立于游戏画面的 UI 缩放 |
| 高对比度模式 | 关闭 / 开启 | 提高角色与背景对比度 40%+ |

#### 9.3.2 色盲模式（Color Blindness）

提供三种色盲模拟适配模式，通过后处理 Color Grading 替换关键色：

| 模式 | 替换规则 | 说明 |
|------|---------|------|
| 关闭（默认） | 无替换 | 正常色觉 |
| 红绿色盲（Protanopia/Deuteranopia） | 血光粉 → 警示黄；毒雾绿 → 青蓝 | 红绿不再依赖区分 |
| 蓝黄色盲（Tritanopia） | 数据蓝 → 暖灯橙；赛博紫 → 锈血红 | 蓝黄不再依赖区分 |
| 全色盲（Achromatopsia） | 全局转为灰度 + 图案/形状区分 | 仅靠亮度与形状区分 |

**关键：** 色盲模式不仅替换颜色，还须为关键信息添加形状/图标/图案辅助区分：
- 资源类型：每种资源有独特图标形状（铁=方块，能量=三角，食物=圆形）
- 危险区域：除颜色外添加边界纹理（斜线/点阵/网格）
- 丧尸类型：除颜色外添加剪影差异（已在 §4 中设计）

#### 9.3.3 对比度与亮度

| 选项 | 范围 | 默认值 | 说明 |
|------|------|--------|------|
| 对比度 | 50%-150% | 100% | 后处理 Contrast 调整 |
| 亮度 | 50%-150% | 100% | 后处理 Brightness 调整 |
| 最低亮度保障 | 固定 | — | 最暗像素不低于 `#05080E`，确保黑暗中可读性 |

#### 9.3.4 按键重映射

- 所有按键可完全自定义重映射
- 支持主/副按键绑定（每个操作可绑 2 个键）
- 支持鼠标 + 键盘混合绑定
- 支持手柄（XInput / DInput）
- 提供预设方案：左撇子方案、单手方案、手柄默认方案
- 建造模式快捷键支持方向键 + 鼠标双重输入

#### 9.3.5 粒子与动效控制

| 选项 | 说明 |
|------|------|
| 装饰性粒子 | 关闭后仅保留功能性粒子（爆炸/弹道/受击），关闭环境飘浮粒子/雾气粒子 |
| 屏幕抖动 | 关闭后所有 Screen Shake 效果归零 |
| 镜头跟随平滑 | 关闭后镜头硬切，减少动态模糊感 |
| 动画速度 | 0.75x / 1.0x（默认）/ 1.25x，影响所有角色动画播放速度（不影响游戏逻辑速度） |

#### 9.3.6 闪烁控制

- 所有闪烁效果频率 ≤ 3Hz（符合 Photosensitive Epilepsy 分析标准）
- 提供"关闭所有闪烁"选项：
  - 霓虹灯管闪烁 → 改为常亮
  - 警报脉冲 → 改为静态红色边框
  - 全息扫描线 → 改为静态半透明
- 闪电效果（电磁风暴天气）提供关闭选项

#### 9.3.7 音频可访问性（与音频设计协调）

> 注：音频可访问性细节由阮和鸣负责，此处仅列出视觉相关的音频-视觉联动项。

- 关键音频事件（丧尸接近/基地被攻击/低血量）须有视觉等价提示：
  - 屏幕边缘方向指示器（箭头/图标）
  - 色彩脉冲（不同于闪烁，为缓慢渐变）
- 字幕系统：所有对话和旁白须有文字字幕
  - 字幕位置可调（底部/顶部/中央）
  - 字幕背景半透明面板（确保可读性）
  - 说话者标识用不同颜色

### 9.4 可访问性自检清单

资产提交前须通过以下检查：

## 附录 C：待审批与风险事项

### 待用户审批项

1. **视角选择**：本圣经建议俯视 3/4 视角（理由见 §3.1）。若选择侧视，角色/环境/UI 多节规范需大幅调整。
2. **PPU = 32 的选择**：32 PPU 在 1080p 下角色显示偏小但信息量大。若用户偏好更大角色（更接近 Dead Cells 比例），可考虑 16 PPU，但会降低单屏可见格子数。
3. **色板批准**：主色板 6 色是否覆盖用户的视觉预期？是否需要追加/替换特定颜色？
4. **可访问性分级 = Standard**：是否需要提升至 Comprehensive？

### 与引擎/管线相关的风险

1. **URP 2D Light 数量限制**：20 个 2D Light 的预算在密集霓虹区域（如赛博城区残骸）可能不够。建议程基岩评估 URP 2D Renderer 的光源合批能力，必要时使用 Sprite 自发光替代部分 Light 2D。
2. **Pixel Perfect Camera + 动画**：Unity 2D Pixel Perfect 包在某些 Unity 2022.3 版本中与 Cinemachine 存在兼容性问题，建议程基岩验证。
3. **Y 轴排序性能**：大量使用 Sort by Y 在同屏 50+ 角色时可能有 CPU 排序开销，建议程基岩评估是否需要自定义排序脚本优化。
4. **Shader 开发需求**：防护罩六边形网格、全息扫描线、故障效果需要自定义 Shader，须与程基岩确认 URP Shader Graph 可行性。
