## 1. 大楼整体结构

### 1.1 视角与比例

| 维度 | 规格 |
|------|------|
| 视角 | 俯视 3/4 视角（Top-Down 3/4 View），正交投影 |
| 总像素尺寸 | **320 × 400 px**（宽 × 高，建议画布） |
| PPU | 32（1 Unit = 32px） |
| Unity 世界尺寸 | 10 × 12.5 Units（宽 × 高） |
| 碰撞体尺寸 | 208 × 96 px = 6.5 × 3 Units（底部占地格数：约 6×3 格） |
| 占地面积 | 约 6 × 3 建造格（192 × 96 px），游戏层中占中大型建筑位 |

> **尺寸推导说明**：美术圣经 §3.2 定义建造格 = 32×32 px。7 层大楼在俯视 3/4 视角下，宽度约 6.5 格，高度（含屋顶天线）约 12.5 格。这是单屏内既能看清大楼细节、又不遮挡过多游戏画面的合理尺寸。

## 2. 末日破损设计

### 2.1 三个破损等级定义

| 等级 | 名称 | 描述 | 墙体完整度 | 窗户完整度 | 结构完好度 |
|------|------|------|-----------|-----------|-----------|
| **1** | 完好（Intact） | 仅表层破损，结构完整 | 90-100% | 80-100% | 100% |
| **2** | 局部破损（Damaged） | 部分墙体剥落，有露天洞 | 60-80% | 30-60% | 80-90% |
| **3** | 严重破损（Heavily Damaged） | 结构暴露，墙体大面积缺失 | 30-50% | 0-30% | 60-70% |

**每层破损等级分配**（基于功能合理性）：

| 楼层 | 破损等级 | 理由 |
|------|---------|------|
| R-屋顶 | **3** | 设备层直接暴露在末日气候中，锈蚀最严重 |
| 7F | **3** | 顶层受风雨侵蚀最严重，设备机房半坍塌 |
| 6F | **2** | 高级住宅区玻璃大面积破碎但墙体尚好 |
| 5F | **1** | 中层住宅相对完好，只有剥落和裂缝 |
| 4F | **2** | 阳台坍塌 + 墙面剥落 |
| 3F | **1** | 底层商铺维护较好（有人活动痕迹），霓虹招牌保护了部分墙面 |
| 2F | **2** | 雨棚坍塌导致上部墙体暴露 |
| 1F | **2** | 入口层有大片涂鸦和弹孔，但卷帘门保持了结构 |

### 2.2 破损视觉元素清单

| 破损类型 | 绘制建议 | 出现楼层 |
|---------|---------|---------|
| **墙体裂缝** | 1-2px 宽的锯齿线，从窗口/墙角向外延伸 | 所有楼层 |
| **混凝土剥落** | 墙体边缘的不规则斑块，露出内部砖色/铁锈色 | 2F, 4F, 6F, R |
| **钢筋外露** | 垂直/水平的 1px 直线，铁锈棕 `#7A4E2D` + 骨白 `#D4C5A0` 高光 | 4F, 7F, R |
| **破碎窗户** | 窗框残存 + 窗格内碎玻璃反射（骨白色 1px 斜线） | 6F（最多）, 7F |
| **阳台坍塌** | 倾斜的阳台板，仅剩一侧悬挂，露出下方铁架 | 4F（一个阳台） |
| **弹孔** | 1px 大小的暗色圆点，分布不均匀，集中在 1F 入口两侧 | 1F, 2F |
| **锈蚀痕迹** | 从屋檐/窗台/管道处向下流淌的竖向锈迹，铁锈棕 `#7A4E2D` 50% 透明度 | R, 7F, 4F |
| **涂鸦** | 褪色的赛博涂鸦（暗紫/暗粉），线条风格 | 1F, 2F |
| **苔藓/污渍** | 墙角的深色污渍块，暗灰绿 `#3A4A3A` | 1F, 4F |
| **电缆垂落** | 从上层垂下的断裂电缆，1px 宽的深色线 | 6F → 5F, R → 7F |

### 2.3 "繁华 vs 废墟"的视觉冲突设计原则

**原则**：每层必须同时包含至少一个"霓虹繁华"元素和一个"废墟破损"元素，且两者在视觉上相邻/交叉。

| 楼层 | 霓虹繁华元素 | 废墟破损元素 | 冲突位置 |
|------|------------|------------|---------|
| R-屋顶 | 天线顶端紫光脉冲点 | 锈蚀通风管 + 半坍塌设备 | 光点直接照在锈迹上 |
| 7F | 窗户后的数据蓝应急灯（微弱） | 大面积破损墙体 + 外露钢筋 | 光从破裂处漏出 |
| 6F | 暖橙 `#FF8C00` 窗户内透光 | 破碎玻璃窗 > 50% | 暖光从碎玻璃中透出 |
| 5F | 楼层线灯带（数据蓝） | 墙面细小裂缝 | 灯带横跨裂缝 |
| 4F | 阳台底部 LED 灯条 | 坍塌的阳台铁架 | 灯条挂在断裂处 |
| 3F | 大招牌「赛博紫」全幅发光 | 招牌边缘的混凝土剥落 | 紫光映在剥落墙面 |
| 2F | 次招牌「血光粉」发光 | 雨棚残骸斜压在招牌上方 | 粉光从雨棚下漏出 |
| 1F | 门头霓虹灯框（数据蓝） | 锈蚀卷帘门 + 弹孔 | 蓝光透过卷帘门缝隙 |

### 3.3 动画类型推荐

| 动画类型 | 缓动曲线 | 适用光源 | 说明 |
|---------|---------|---------|------|
| **呼吸（Breathing）** | Sine 波，周期 2-4s | N2, N4, N7 | 缓慢亮暗循环，模拟电源波动 |
| **脉冲（Pulse）** | 快速 Attack + 慢速 Decay | N1, N8 | 短促亮起后缓降，模拟数据信号 |
| **故障闪烁（Glitch Flicker）** | 随机二值（开/关）+ 像素块抖动 | N5, N6 | 模拟霓虹灯管故障，2% 概率每帧触发 |
| **静态（Static）** | 常亮（无动画） | N3 | 稳定内透光，偶有 0.1s 的供电波动 |

// Shader 伪代码思路

### 7.3 故障闪烁模式（N5 / N6 招牌）

建议实现以下 4 种故障子模式，通过 Random 切换：

| 子模式 | 视觉表现 | 持续时间 | 触发概率 |
|--------|---------|---------|---------|
| **Mode 0 · 常亮** | 正常发光 | 5-15s | 70%（默认态） |
| **Mode 1 · 全灭** | 整块招牌熄灭 | 0.1-0.5s | 15% |
| **Mode 2 · 局部块闪烁** | 招牌的 1/4 或 1/3 区域闪烁 | 0.3-1.0s | 10% |
| **Mode 3 · 像素抖动** | 招牌文字/图案的水平偏移 1-2px | 0.1-0.3s | 5% |

**在 Shader 中实现故障模式的思路：**

```hlsl
// 伪代码 — 在 fragment shader 中
float4 frag(v2f i) : SV_Target
{
    float4 color = tex2D(_NeonTex, i.uv);
    
    // 如果是紫色或红色像素（即霓虹招牌区域）
    if (isNeonColor(color))
    {
        float glitchState = GetGlitchState(_Time.y, _RandomSeed);
        
        // Mode 1: 全灭
        if (glitchState == 1) color.a = 0;
        
        // Mode 2: 局部块闪烁 — 根据 UV 坐标判断
        if (glitchState == 2 && IsInBlockZone(i.uv, _BlockIndex))
            color.a = 0;
        
        // Mode 3: 像素抖动
        if (glitchState == 3) 
        {
            float2 offset = float2(1.0/320.0 * sign(sin(_Time.y * 100)), 0);
            color = tex2D(_NeonTex, i.uv + offset);
        }
    }
    
    return color;
}
```

### 7.4 颜色循环（Color Cycle）可选功能

当前设计中霓虹灯颜色已固定（不循环颜色），有以下两个例外可考虑：

| 位置 | 当前颜色 | 可循环颜色 | 周期 | 备注 |
|------|---------|-----------|------|------|
| **N5 大招牌边缘装饰线** | 赛博紫 `#B026FF` | 赛博紫 ↔ 数据蓝 | 6s 渐变 | 仅招牌外框装饰线，不影响招牌文字 |
| **N1 天线顶光** | 赛博紫 `#B026FF` | 赛博紫 ↔ 血光粉 | 3s 渐变 | 仅中间最高的天线 |

### 7.5 与 URP 2D Light 的配合建议

| 项目 | 建议 |
|------|------|
| **是否使用 URP Point Light 2D** | **不使用**（Draw Call 预算留给游戏内的动态光源，如防御塔、爆炸等） |
| **大楼发光表现方式** | 纯 Sprite 自发光（Emissive Sprite）+ Additive 混合渲染 |
| **地面光晕** | 如果预算允许，在大楼底部加 1-2 个 Point Light 2D 投射地面光晕；否则在场景 Tilemap 上加一张地面光晕 Sprite |
| **性能预算占用** | 大楼本身：2 个 SpriteRenderer（Base + Neon）= 2 Draw Calls |
| **与场景交互** | 玩家角色经过大楼前方时，Y 轴排序：玩家在前 → 玩家遮挡大楼底部；大楼在前 → 大楼遮挡玩家角色头顶 |

### 7.6 可访问性：闪烁控制

根据美术圣经 §9.3.6（可访问性）：

> 所有闪烁效果频率 ≤ 3Hz；提供"关闭所有闪烁"选项

| 当前设计 | 是否符合 ≤ 3Hz？ | 说明 |
|---------|-----------------|------|
| N1 脉冲 (1.5s = 0.67Hz) | ✅ | 远低于 3Hz |
| N2 呼吸 (2.5-3.0s = 0.33-0.4Hz) | ✅ | 远低于 3Hz |
| N4 呼吸 (4.0s = 0.25Hz) | ✅ | 远低于 3Hz |
| N7 呼吸 (2.5s = 0.4Hz) | ✅ | 远低于 3Hz |
| N8 脉冲 (1.2s = 0.83Hz) | ✅ | 低于 3Hz |
| **N5/N6 故障闪烁** | **需注意** | 最短全灭时间 0.1s，单次闪烁换算为 10Hz，但非连续周期性闪烁。建议提供一个开关，关闭后改为常亮 |

**建议**：在游戏中提供"霓虹灯闪烁"开关（默认开启）：
- 开启：所有霓虹灯按表格中的动画方式运行
- 关闭：所有霓虹灯以 80% 强度常亮，取消所有故障/脉冲/呼吸动画

## 附录 B：关键视觉决策摘要（供团队对齐）

| 决策 | 选择 | 理由 |
|------|------|------|
| **楼体 vs 霓虹灯** | 方案 B：两张 Sprite 叠加 | 修改灵活，开发门槛适中 |
| **发光方式** | Sprite 自发光 Additive，不使用 URP Point Light | 节省 Draw Call 预算，保持像素硬边 |
| **破损分布** | 上重下轻（顶部严重破损，底部相对完好） | 符合末日逻辑（上层风蚀更重）+ 底层商铺受幸存者维护 |
| **霓虹色分配** | 赛博紫 → 招牌和灯带；数据蓝 → 玩家势力色灯带和内透；血光粉 → 危险/次级招牌 | 与美术圣经 §2 色板用途一致 |
| **光源动画** | 呼吸（慢）> 脉冲（中）> 故障（随机）> 静态（默认） | 避免过度闪烁，符合可访问性要求 |
| **可访问性** | 提供"霓虹闪烁"开关 | 关闭后所有灯光常亮，消除闪烁风险 |
